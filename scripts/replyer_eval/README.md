# 主播表达引擎离线评测

评的是主播的表达引擎（Replyer）：拿到交接稿和聊天记录后说出来的那一句台词。生产源文件是
`src/agents/streamer/replyer.py` 与 `src/agents/streamer/prompts/amaidesu_replyer*.md`。
评测器用生产的 `Replyer` 渲染输入、真调模型，不复制提示词和渲染规则。

## 「谁说的、谁做的」（attribution.py）

量台词有没有把玩家的话、玩家的举动安到别人头上。用例是合成的，照着线上出过的三种错写：

| 组 | 情形 | 判错 |
| --- | --- | --- |
| gift | 玩家扔来东西，交接稿写成凭空到手或没写是谁 | 说成天上掉的、来路不明、问是谁给的 |
| speaker | 玩家在公屏说话，聊天记录上一句刚点过女仆、宠物或观众的名字 | 台词把这句话安到那个名字头上 |
| about_her | 玩家的话说的是她做的事（她挖了自家地板、她老是蹲） | 反过来劝玩家别这么做 |
| control | 东西是怪掉的、或没有玩家找她 | 台词把东西安到玩家头上、冒出没出现的玩家名 |

每条用例写明禁用说法（正则），台词命中任何一条就算这一次说错。玩家的话和动作经生产的游戏账本
入账、出账，得到交给表达侧的「游戏里最近找你的人」与回应对象，和线上同一条路径。玩家名一律用
"阿甲""阿乙"这类占位。

| 指标 | 阈值 | 算法 |
| --- | --- | --- |
| 误归因率 | <= 0.1 | 命中禁用说法的台词数 / 全部台词数（每条用例按 `--samples` 重复） |

报告另按组列出错的次数，并附每条用例交给模型的输入（`--show-input`），方便对照是输入缺了什么还是模型没照着说。

### 模型

线上表达引擎用哪个模型以直播机的 `config/model.toml` 的 replyer 档位为准。这组用例在不同模型上
差别很大：强一些的模型不给结构化的人和回应对象也很少说错，复现线上错误要用线上同款模型。
报告记下了实际用的模型和温度，比较改动前后时两次要用同一个模型。

### 怎么跑

```bash
uv run python scripts/replyer_eval/attribution.py
```

dry（默认）不调模型，只用生产代码把每条用例的输入渲染一遍，检查样本完整。

```bash
uv run python scripts/replyer_eval/attribution.py --live --out <报告.json> --model <模型名> --api-key <密钥> --base-url <端点>
```

`--samples` 每条用例采样几次（默认 3），`--temperature` 默认 0.2，和生产 replyer 档位一致。连接参数也可以用
环境变量 `LLM_MODEL`、`LLM_API_KEY`、`LLM_BASE_URL` 给出；密钥不写进报告。
