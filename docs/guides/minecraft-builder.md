# 新建造器接入 Amaidesu

Amaidesu 将设计与施工分开：按需建筑设计 Agent 读取资料、生成草稿并调用 Mod 校验；Minecraft Agent 接收设计产物引用，再决定何时启动施工。
运行机制见 [Minecraft Agent 架构](../architecture/minecraft-agent.md#按需建筑设计)。此接入面面向新建造器，不要求实现旧语义建造协议。

## 契约的权威位置

| 内容 | 权威代码 |
|---|---|
| 功能开关、预算、目录 URI 与 Mod 工具原名绑定 | [MinecraftBuilderConfig](../../src/agents/minecraft/builder/config.py) |
| 资源目录、资料元数据、设计任务与产物外壳 | [建造数据模型](../../src/agents/minecraft/builder/models.py) |
| 资源读取与 Schema 校验 | [MinecraftBuilderBackend](../../src/agents/minecraft/builder/backend.py) |
| 场景操作、受理回执、终态结果与施工请求 | [MinecraftSceneProtocol](../../src/agents/minecraft/builder/scene_protocol.py) |
| 游戏侧受理、状态、修订、取消与施工入口 | [MinecraftBuilderController](../../src/agents/minecraft/builder/controller.py) |
| 可运行的资源与 Mod 协议示例 | [建造器协作测试](../../tests/agents/test_minecraft_builder.py) |

配置随 Minecraft 的嵌套 Schema 生成，Mod 工具绑定填写 server 原始工具名；注册表全名由工具系统派生。
独立设计模型用途的权威声明位于[模型 Schema](../../src/modules/config/model_schemas.py)。已有配置缺少该用途时沿用游戏模型列表并落盘补齐，明确设置的设计模型保持不变。

## Mod 需要提供的行为

资源目录必须通过 MCP 的具体资源列表可发现。目录引用设计 Schema 与教材条目；标为任务基础教材的正文在委派启动后注入，其余正文由设计 Agent 按需选择。
目录中的 Schema 与教材 URI 应指向所声明版本的固定内容，避免目录读取与正文读取之间发生无声替换。
能力与设计字段从 Mod 的实际类型或注册定义导出，教材条目声明其需要的能力及兼容版本。教程内容可以逐步补充，空教程目录不妨碍客户端接入。

设计 Schema 使用客户端支持的 JSON Schema 方言，并包含所需的本地定义。客户端不会联网补齐外部引用。
教材中的 `$ref` 等原文不会进入本地模板变量替换。新增形状或材料技法只要仍符合现有协议外壳，就由 Schema 和教材描述，无须在 Amaidesu 添加专用分支。

客户端复用 MaiCraft 的四工具协议，以设计能力下的场景操作创建、修改或检查模型；施工由父级使用建造能力单独发起。
设计操作会编译并原子保存作者场景，检查模型表达、体素展开、注册方块和状态支持范围，不证明通行、材料齐备或现场可施工。
受理回执不代表设计成功；客户端核实任务终态中的真实结果，才接收带版本依据的场景编号。
产物引用对应不可变的作者场景及其锚点；场景读取、预览和施工仍由当前 Mod 编译器解释，因此同时核对编译契约版本。
修改生成新场景编号并保留父版本，不能在同一个编号下替换旧图。

模型可以按名字读取对象或组件定义并分次提交完整编辑；未提到的对象保留，嵌套字段整体覆盖，组件和材料定义按名整条替换。
检查接口的分页标记原样保留，不把单页摘要当完整模型。预览不启动角色施工；当前适配器消费结构化结果，图像输入另行扩展。

施工工具由 Minecraft Agent 调用，消费设计引用、版本、现场上下文与幂等键。
Mod 必须在受理前重新核实现场和版本，成功受理后立即返回施工任务号，由既有任务查询和 attention 通道报告真实进展。
设计操作和施工使用不同幂等键；不同设计内容或修订也分键。相同操作的传输重试复用原键。
施工受理结果未明时保留同一键核实，禁止直接换图再施工。场景编号与冻结施工项目的编号不能混用。

## 回复完整性

建造调用不发送宿主的固定输出 token 上限，不使用模型用途或 provider 的默认额度裁剪回复。
模型服务仍有自己的容量边界；客户端保留结束原因，未正常结束时整轮工具都不执行，并将原文与错误反馈给模型。
严格工具参数拒绝语法补齐、重复键、非有限数字及非对象根值。失败的一轮会撤销旧候选，避免从半份新设计退回误交付旧图。
输出过长时可通过具名对象和组件分次提交完整 JSON；不把多个截断字符串拼成设计。上下文或资源预算超限时明确失败，不静默裁剪。

## 运行与故障语义

未发布资源目录、受理或任务查询通道不可用、能力不兼容或 Schema 不合法时，设计任务明确失败。
Minecraft Agent 可以修订要求、明确取消任务或上报困难。设计完成只解除设计义务；原要求是建好时，施工成功前仍有交付门禁。

父 Agent 暂停时子任务在步骤与工具调用之间挂起。停止游戏先终止子任务、移除设计工具，再释放父级 MCP 连接。
暂停期间仍可取消设计；任务总时限按墙钟计算，包含暂停时间。设计可与已有施工并行，同一角色同时只受理一份建造器施工。
本地取消后的迟到模型结果不会激活新动作。已经启动的 Mod 施工需要通过 Mod 任务控制单独取消并核实，不把取消设计等同于回滚世界。

任务与设计结果只在当前 Minecraft Agent 会话内保留；进程重启不自动恢复或重放施工。
已收尾的设计按配置限量保留，未处理的施工义务不会因历史清理而消失。

教材正文、风格选择与 JSON 案例由 Mod 的建造目录维护，Amaidesu 不保存另一套风格提示词。
基础方法先指导需求收敛、体量和差异化，再选相关风格与技法；同任务保留完整正文和版本依据，重复读取复用已固定内容。
新增风格只需在 Mod 发布兼容资源，不需要修改游戏 Agent。编译通过不等于外观优秀，模型输出质量和实际游戏观感仍需单独验收。
