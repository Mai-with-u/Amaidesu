# ADR-014：配置体系六文件重构

- 状态：已接受（2026-09-12 定案并实现）
- 日期：2026-09-12
- 实现提交：`6e593a9e`（六文件配置域落地）→ `8484c2bc`（加载管线阶段化）→ `b0ba80be`（写回推进与热重载策略）→ `858a5ce7`（dashboard 配置 API 自描述重写）→ `28c38b37`（合流工具线批次）

## 背景（Context）

旧体系（core/model/agents/tools/memory/storage/background 七个文件）在落地中暴露四类问题：

1. **中央树内联组件字段**：组件配置字段在 `core_schemas.py` 等中央文件重复定义，与组件包内消费代码必然漂移；迁移期还残留「升级钩子 / 迁移脚本 / Schema 生成器」三套机制互为前置。
2. **全局单版本**：单一全局版本号管全部文件，改一个采集器字段全量升版本，升级钩子被迫全文件扫描。
3. **迁移机制悖论**：本项目用户量 = 1，配置值迁移（旧键 → 新键映射表）维护成本高于价值；真正需要的是结构升级（补默认 / 清冗余）而非值迁移。
4. **WebUI 手写校验**：dashboard 配置 API 用三张硬编码映射表（section → 文件 / 根模型 / 标签）加手写类型校验复刻 Pydantic，行为保真靠人肉。

## 决策（Decision）

核心一句：**每文件一个版本、每组件一份包内权威 Schema、一条加载管线；值迁移不做，结构漂移自动写回。**

### 六文件按域拆分

`agents / collectors / tools / model / storage / infra`（`config/` 目录每域一文件）。启用开关收敛两处：`[agents].enabled` 与 `collectors.toml` 顶层 `enabled`；全局工具停用为 `[tools].disabled_tools`（重启生效）。原 `core.toml` 内容归位 infra.toml 与 agents.streamer 子树；`memory.toml` 并入 storage.toml；`background.toml` 并入 agents.streamer（后台维护随 Agent 生命周期）。

### 每文件独立版本

每文件自带 `[meta].version`；升级钩子在注册表（`upgrade.py`）声明目标版本区间，加载时按文件独立推进（改单文件不带动他文件）；缺失 `[meta].version` 硬错。跨文件钩子声明目标文件、双写双版本同升。

### 组件包内权威（单一事实源）

组件配置的唯一权威是组件包内 `ConfigSchema`（详见组件开发指南「配置 Schema 约定」）；中央树（`src/modules/config/*_schemas.py`）只留域聚合段与槽位。组件注册表（`registry.py`）以显式 import 链装配，漏登记启动期断言暴露。采集器子段在加载管线内按注册表分发校验，漂移路径以 `<组件名>.<字段>` 前缀并入宿主报告。

### 单一加载管线（六阶段）

`load_config_dir`：①全读 → ②跨文件钩子 → ③每文件钩子 → ④ Pydantic 校验（硬错，无 raw dict 降级）→ ⑤ 漂移写回（全量序列化写盘 + 批次备份 + 自写压标，内容不变短路）→ ⑥ 合并视图（剥 `[meta]`，scope 展平）。校验失败启动即停，不做降级兼容——配置错误是部署错误。

### 值迁移不做，结构漂移写回

用户量 = 1 的现实下不做旧值迁移映射表；结构漂移（缺键 / 冗余键）由写回按 Schema 全量写出补齐/物理删除，过程走日志可见，写回前生成批次备份（`config/old/<批次>/`）。管线自写压标（TTL）防 FileWatcher 重入；重载按段策略分流——`infra` 为 hot 段即时回调生效，其余五文件诚实提示待重启；重载失败保留旧配置继续运行（不打断直播）。

### WebUI 并入同管线

dashboard 配置 API 的三张映射表与手写校验删除，改根 Schema 自描述协议（`__file_name__` / `__section_label__`）动态分组；写路径统一 `update_config_values`（校验硬错 → 备份 → 压标 → 注释重生成）；`meta.version` 只读 422；敏感字段 GET 返回「已设置」占位、占位回写 422、显式清空提交空串。

## 替代方案（Alternatives）

### 保留七文件 + 全局单版本

维持 core/model/agents/tools/memory/storage/background 拆分与单一全局版本号，只修升级钩子。

**拒绝**。组件字段在中央树内联的耦合不解决（同一字段两处定义必然漂移）；任何域的结构变更都推高全局版本，升级钩子被迫全文件扫描，改动一个采集器牵动全部文件。

### 自动值迁移映射表

为旧键 → 新键维护一张迁移映射表，首启自动搬运用户旧配置值。

**拒绝**。用户量 = 1，映射表的编写与验证成本高于手搬十几个值；且映射表本身是"迁移机制"的复活——与"不建机制"的定案相悖。旧文件归档保留 + 基线重生成 + 手工搬关键凭据，一次性成本更低。

### 保留 WebUI 手写字段校验

dashboard 维持三张映射表 + 手写类型/约束校验（复刻 Pydantic 规则），只修映射表数据。

**拒绝**。手写校验与 Pydantic 的行为保真靠人肉对账（R6），每加一个约束两处同步；统一走 Schema 校验后保真由实现保证而非测试兜底。

## 后果（Consequences）

- 新增组件 = 包内定义 ConfigSchema + 注册表登记 + （采集器）collectors.toml 加段/名单，框架零改动；漏登记启动即暴露。
- 配置结构变更 = 改 Schema + 升 `[meta].version` + （需要值变换时才写）钩子；纯新增字段由写回自动补默认。
- 旧七个文件升级到六文件**无自动迁移**：用户首次以新版启动会生成六文件基线，旧文件不读不删——一次性手工搬运（用户量 = 1 下接受）。
- 配置错误（类型违约 / 未注册段 / 缺版本）启动期硬错退出，治理窗口前移。
