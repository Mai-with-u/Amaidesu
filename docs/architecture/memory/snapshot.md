# 档案快照

> 每个整理过的正式场另留一份档案快照，接住前几场仍然成立的事；记忆摘要只读一份快照。全局规则见[总览](README.md)。

代码在 `src/agents/streamer/memory/rolling.py` 与 `settle.py`。

## 为什么需要快照

每份场次档案只写一场的事，碰上一场短的、乱的，前面几场的事就从摘要里全掉出去。档案快照接着前几场仍然成立的事往下带。

## 快照行结构

- **快照只引用原行**：每行引用一条 `archive_lines`，另记位置、是否长期成立、最近一次写下或再提起它的那一场的开播时刻。
- **原行删了快照跟着撤**：原行被删（删单行、按句删台词、改彩排、删场次）时外键级联从所有快照撤掉；删观众改的是原行文本，快照读到的也是替换后的。
- **留下的行一个字节都不变**：标题、原话、证据、出自哪一场、关联哪个存档都不改。

## 模型只挑不改写

**上一份快照**指开播早于本场的最近一份同类型快照，不看时长。它每行编号"旧N"，注明原话、在哪个存档、是否长期成立，交给模型；没列出的行一律保留。

模型能做的三种操作：

| 操作 | 要求 |
|---|---|
| 保留 | 可以注明本场又提起它的那一行（记为再提起），可以重标是否长期成立 |
| 去掉 | 理由必须以了结、不成立、记错、被取代四类之一开头，并指出本场哪一行台词是证据（代码核对它确实是本场播出的台词）。"这场没提到""一次性的事"不算理由 |
| 替换 | 给本场一行台词里的原话片段，过与新事同一个"一字不差"的校验。被换掉的是长期成立的事，新行也算长期成立（模型明确写了不成立的除外） |

同一件事写了两行时可以注明与哪一行重复去掉其中一行；那一行本场被替换或带证据去掉了，这一行跟着它走；那一行自己也是按重复去掉的（互指、绕成一圈），这一条不采纳。

不合规的操作不采纳、旧行照留，连同理由写进整理报告——既没被合格地去掉、也没被替换的旧行一律留着。

## 档位取舍

**取舍由代码按固定档位做**，模型不凭感觉删。各档从前到后：

| 档 | 内容 |
|---|---|
| 0 | 人放回或新增的行（`pinned`）：排最前、一行不挤，不占后面各档名额 |
| 1 | 代表性事件（`highlight`）：按游戏存档各留一份名额；未核实到的完成说法不能当代表性事件 |
| 2 | 每个存档的取名类长期成立的事：压成紧凑名字表 |
| 3 | 每个存档的其余长期成立的事：补足【这个世界里】的名额 |
| 4 | 游戏本场新进展 |
| 5 | 前两场保留进展 |
| 6 | 不关联游戏的直播间长期成立的事 |
| 7 | 直播间普通事件 |

各档展示名额与跨存档总安全上限在 `rolling.py` 的档位表里。被挤出的本场新事照样写成本场档案行，回忆工具查得到，只是不进快照；挤出的行写进整理报告。

## 重新整理、兜底与冷启动

- **重新整理**：第 N 场的快照从它之前最近一份快照重新算，此前做过的去掉、替换随之作废；之后各场的快照不重放。要结果带到摘要里，按时间顺序把之后的场次依次重新整理。
- **兜底**：输出里没有对旧行的操作（或整个输出为空）时上一份原样保留；操作不是列表、上一份读不出来，都算整理失败，下次再试，上一份快照原样留着。
- **冷启动**（指升级后数据库里还没有任何快照的情况）：存储升级时库里还没有快照、而最近一个已结束的正式场已经按旧逻辑整理过，迁移把它放回待整理，启动补整理在现拼的基底上重新整理它。不需要运维步骤。
