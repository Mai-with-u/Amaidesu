# 审核与删除

> 人对记忆的三类干预：事后审核整理结果、批准观众定下的事、删除与遗忘。保留期与删除函数的存储面见[存储 - 隐私与保留期](../storage.md)。全局规则见[总览](README.md)。

## 人工审核

整理照旧自动生效，人在 WebUI 记忆页事后改；观众定下的事要人批准才进记忆。

**审核操作**：改标题、标或取消"长期成立"、把被挤出或去掉的行放回最新快照、取消放回、从这一场她播出的台词里截一段原话新增一行、删行、标已审。

- 改过标题或长期成立标记、人新增的行**锁住**：之后的整理不能去掉或替换（整理报告写"人改过的行只有人能让"），也改不了它是不是长期成立的事。只有"最近被提起"按本场台词证据照常更新。
- 放回与新增的行在快照取舍里排第 0 档，不挤、不占长期成立的事的名额；**一份快照的放回名额有限**，满了界面提示、要先取消一条放回才能再放回或新增。取消放回的行还在快照里，之后按规则取舍。
- 锁住但没放回的行被挤出快照不算"去掉"：锁住只是模型不能改它、删它，要不要一直留在摘要里由放回决定。被挤出去的行还在档案里、回忆查得到。
- 原话不能改。每次操作记一条改动记录（表 `memory_edits`），与档案同寿命。

## 待审候选

候选（`viewer_candidates` 与玩家自述表）在批准前对她完全不可见——摘要、回忆、检索索引都不读候选表：

| 类型 | 怎么产生 | 批准后 |
|---|---|---|
| 观众定下的事 | 写档案那次调用顺带列出：观众起的名字、定的设定或梗、说游戏世界的事，她在回复那条真实观众弹幕的那一行接受了、自己却没复述 | 写成一行"观众定下的事"的档案行，锁住，放在最新快照最前面 |
| 她说欠着的事 | 找承诺那次调用顺带列出：她说"上次答应过""欠大家的"，账上（未了结、已了结）找不到对得上的 | 登记成一条未了结承诺 |
| 老观众的近况与喜好 | 老观众主动说起、她当场接住的持续性日常或喜好（`kind="viewer_self"`，标题以 `ta` 开头） | 原地留在 `viewer_candidates`，不进全局档案与承诺；仅在该老观众场内开口时生成老观众线索 |
| 玩家自述 | 游戏玩家在游戏公屏说的关于他自己的事、她当场接住了 | 进另一张待审表 |

每类每场的名额在 `settle_candidates.py`。

核对口径（代码判，不靠模型自觉）：

- **观众定下的事**：两段原话都要一字不差。模型另写观众定下的名字或梗词，必须在标题与那条弹幕原文里原样出现；观众只问了名字、名字是她自己起的不列。含个人信息模式的整条丢掉只计数。
- **她那行回应里点了那位观众的名**（弹幕上的名、现名、曾用名），记忆摘要、记忆线索渲染时换成"那位观众"，库里的原话不改，回忆照旧按跨场打码。人批过的标题不换，原话里和观众定下的那个词相同的那一段也不换。
- **候选的寿命**：待审有时限，超时没人审自动删掉；驳回的留着，同一条以后不再列。候选挂在观众那条弹幕、她那句回应与观众行上，删观众、"忘了我"、按句删、删场次随外键一起删；挂在别人弹幕上、只是提到 ta 的候选不删，昵称换成"一位观众"。

## 删除与遗忘

- **删一条记忆**：记忆页可以给承诺了结、判误记、彻底删除、手建；档案可以删单行、改标题、标长期成立、放回、新增；整理状态里没通过校验的清单可以照原话手建；待审候选可以批准、驳回；"游戏里的人"可以删玩家、确认或取消玩家与观众的关联。
- **删单句台词**：复盘页的"本场台词"面板逐句可删（`DELETE /api/v1/review/speech/{chat_id}`）。一个事务里删这句台词、删引用它的档案行（档案行唯一证据就是这句台词）、清空引用它的承诺的原话（承诺行保留，记忆页显示"原句已删除"）。被诱导说出口的一句、说漏的观众私事走这里，不必连整场一起删。
- **"忘了我"**：观众发命中短语后，写库的入口在判场次之前就停止记录 ta（外部 ID 摘要进不记录名单、观众行记下删除请求、当前显示名进本场打码名单），删除推迟到发令之后第一次下播后的清理、最迟有上限；执行前本人发撤回短语即取消。判据与短语表在 `src/modules/storage/privacy.py` 与 `storage.toml` 的 `[privacy]` 段；规划器由线索推送收到同一判定函数的遗忘回执，答应与否与代码一致。

  ```mermaid
  sequenceDiagram
      autonumber
      participant V as 观众
      participant L as 写库这一侧
      participant PL as 规划器
      participant C as 下播清理

      V->>L: 弹幕“忘了我”
      Note right of L: 判场次之前就停记 ta<br/>外部 ID 摘要进不记录名单<br/>观众行记下删除请求<br/>当前显示名进本场打码名单
      L-->>PL: 遗忘回执（同一判定函数）
      Note over V: 发令前本人发撤回短语即取消
      Note over C: 删除推迟到发令之后第一次下播后的清理，最迟有上限
      C->>L: 清掉名单里的人
  ```

- **打码**（把某个人的真名换成"一位观众"这类称呼）：名单上的人发言后，她台词里 ta 的显示名在写库前就换成"一位观众"；回忆工具的跨场结果同样打码。游戏情境发给嵌入服务前，已知的名字（身边看到的玩家、本场发过弹幕的观众、游戏公屏里说过话的人）先换成"玩家"。
### 下播收尾的顺序

主播 Agent 接管下播清理（启动时关掉写库那一侧的 `cleanup_on_live_ended`，停止时还回去）。道别那一轮跑完后，后台按序：

  1. 等道别句播完（有超时上限）。
  2. 等本场下播整理结束（成功失败都继续）。
  3. 等最后几句台词与观众消息写库落完。
  4. 跑保留期清理与到期的"忘了我"删除。
  5. **最后**清空本场打码名单——因此道别句里叫到的名字仍会被打码。

  每一步有超时上限，超时不挡后续清理；清理失败记错误，由下次启动的启动期清理与定时器兜底。道别期间已经开了新场次时仍跑清理，但不清打码名单。

  ```mermaid
  sequenceDiagram
      autonumber
      participant SA as StreamerAgent
      participant SP as 语音管线
      participant SE as 下播整理
      participant LG as 写库这一侧
      participant MS as 打码名单

      Note over SA: 道别那一轮跑完
      SA->>SP: 等道别句播完
      SA->>SE: 等本场整理结束
      SE-->>SA: 成功或失败都继续
      SA->>LG: 等最后几句台词与观众消息写库
      SA->>LG: 跑保留期清理与到期的“忘了我”删除
      SA->>MS: 最后清空本场打码名单
      Note over SA,MS: 每一步超时都不挡后续清理
  ```

- **保留期**：`storage.toml` 的 `[retention]` 两个天数默认不自动删除，由使用者按接入方式与合规判断配置；到期的"忘了我"删除与保留期清理在启动时与每次下播后跑。
