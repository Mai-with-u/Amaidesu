# ADR-041：直播画面做成采集流（变化才发布 / 事件只带句柄 / 决策窗首请求尾部看一眼）

- 状态：已采纳
- 日期：2026-10-14
- 实现提交：`53a9a36a1a920923c5ef5d305203e8763bdc630d`（feat(collectors): 新增直播画面采集器）+ `7a467a6f36bd1b3d4c318a7de48c3547e696a50e`（feat(streamer): 决策时可看一眼直播画面）

## 背景（Context）

主播解说时只能从游戏记录、身体近况与查询工具间接知道画面上有什么，描述观感与氛围没有依据。想让主播"常态看画面"，直觉做法是每个决策窗调一次 `vision_look_at_screen`，但它有四个问题：

- **判据不符**：按本项目的组件判据，"被调才看"是工具，"一直在看"是持续流、应做采集器；每窗都调一次截图工具，就是把快照工具当持续流轮询（`reference_tools` 轮询 `minecraft_glance` 已是一例）。
- **采集源不对**：`vision_look_at_screen` 用 mss 截桌面，直播时桌面上可能是 OBS、Dashboard，不一定是观众看到的画面。
- **成本**：10-07 一场 planner 调用 646 次，每次带一张千级 token 的图、且都按未命中缓存计费，代价可观；画面大多数时候并没有变化。
- **缓存与时效**：图若留在历史里每次都重传；画面几秒就过期，决策窗看到的可能是旧画面。

## 决策（Decision）

**画面是一条采集流：采集器低频采样，每帧覆盖写入图像暂存的 latest 槽位；主播在决策窗第一次请求的尾部查询式挂上最新一帧，限频去重。**

- **采集器**：通用采集器 `live_frame`（collectors.toml 开关，默认不启用）。默认经 obs-websocket 截 OBS 当前节目场景（或指定来源），即观众看到的画面；OBS 不可用时可改截显示器。每 5 秒取一帧，缩成 32×18 灰度图与上一张稳定画面比较；差异超阈值或距上次基线刷新超 60 秒时刷新比对基线。取帧失败只记日志按间隔重试。
- **暂存**：每帧覆盖写入进程内图像暂存（`VisionImageStore`）的 latest 槽位；图像本体不进事件流、诊断记录与 WebUI，主播 Agent 查询式取帧。
- **消费**：主播 Agent 只保留最新一帧。`[agents.streamer.live_frame]` 启用且 planner 主模型支持视觉时，Planner 把画面作为一条 user 消息（【直播画面】说明 + 图像句柄）挂在本窗第一次请求尾部，不写进消息序列；画面过时（默认 15 秒）不看、同一帧不重看、两次之间至少隔 15 秒。图像生命周期沿用 ADR-040：只活这一次请求。
- **语义约束**：说明里写明画面只用于观感与氛围，游戏里的数值和进展以游戏记录与查询结果为准，看不清的不要猜。
- **MC 不接**：MC 有结构化观察（MaiCraft observe），像素远不如它精确，继续按需调截图工具。

## 替代方案（Alternatives）

- **每个决策窗调一次截图工具**：违反持续流判据；截桌面不等于观众画面；画面没变也付费。
- **画面进参考段的文字描述（先过 VLM 再给 planner）**：多一次 1–9 秒的 VLM 调用；planner 主模型本身能看图（ADR-037），转述只会丢信息。
- **每次请求都带最新画面**：成本随决策窗数线性增长，且同一画面反复看没有新信息；变化才发布 + 同帧不重看 + 最短间隔才控制得住。
- **字节级指纹判断变化**（text_adv 的 `FrameFingerprint`）：游戏画面每帧都有细碎动画，字节指纹永远不同；缩略图平均灰度差才能分辨"明显变化"。
- **OBS 连接复用 `[tools.studio.obs]`**：采集器读工具域配置会跨配置文件耦合；采集器段单独配置连接参数，连不上时有告警，不是静默失败。

## 后果（Consequences）

收益：

- 主播能看到观众此刻看到的画面，成本按"画面明显变化的次数"计，不按决策窗数计。
- 画面不进历史，不影响前缀缓存；事件流里只有句柄。

代价与需持续关注：

- OBS 连接参数在 `[live_frame]` 段单独配置，需与 OBS WebSocket 设置一致（主机、端口、密码）。
- 单张图的真实 token 成本随模型与分辨率变化，接入后以 API usage 为准调 `max_width` 与间隔。
- 截桌面来源取到的是整块显示器，可能包含非直播内容；默认用 OBS 来源。
- `VisionImageStore` 容量 16 张由画面帧与工具截图共用；画面最快每 5 秒一张，工具截图只需活到下一次请求，目前容量足够。
