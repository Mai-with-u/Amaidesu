# ADR-046：直播内容进 MaiBot 长期记忆（暂定：整场记录回放进直播间会话）

- 状态：草案（暂定方案，等 MaiBot 维护者对"走消息流程还是走导入流程"表态后再定）
- 日期：2026-10-23
- 实现提交：与本 ADR 同笔交付（`git log -- docs/decisions/046-live-transcript-to-maibot-memory.md`）；MaiBot 侧的回放在 AmaidesuBridgePlugin 仓库

## 背景（Context）

"一个麦麦"的记忆互通分两半。读的一半已经做了：主播可经桥接插件查 QQ 麦麦在群里的记忆和对群友的印象。写的一半还缺：直播里发生的事进不了 MaiBot 的长期记忆，私聊麦麦问"上次直播聊了什么"它答不上来。插件能力表只开放了检索，没有写入。

MaiBot 维护者的建议是：把每次直播当成 MaiBot 里的一场群聊，记忆走 MaiBot 自己的聊天摘要流程，再用共享记忆组（`a_memorix.shared_memory_groups`）让 QQ 群和私聊也能查到——不需要开放写入接口。具体落地有两条路：

- **消息流程**：插件声明消息网关，把直播记录作为消息送进一个会话，由聊天摘要吸收。
- **导入流程**：用 WebUI 知识库的"聊天记录"导入。入口要 WebUI 登录，插件调不到，只能每场手动导。

暂定走消息流程。核对 MaiBot 当前实现时发现一个约束：聊天摘要**只在麦麦自己在该会话发出消息后**才检查一次，新增消息达到阈值（默认 36 条）才写；每次只总结最近 `min(chat_summary_writeback_context_length, 新增条数)` 条（默认 36，上限 500）。只收不发的会话永远不会被总结。

## 决策（Decision）

核心一句：**收播后把整场记录交给插件，插件按原始时间顺序回放进一个固定的直播间会话：观众的话作为入站消息，主播的话作为麦麦自己的发言，让 MaiBot 像对待一个普通群聊那样去总结。**

1. **推整场记录**：场次回顾写好（`streamer.recap.written`）时，上报器从库里读这场的全部聊天行（观众弹幕与付费留言、联动对象发言、主播发言；跳过模拟消息），推给插件，地址与近况推送相同（`/live-status`，`type="transcript"`）。挂在回顾事件上而不是收播事件上，是因为进程退出时收播来不及推，而回顾在下次启动时会补写，记录随之补推。失败按 5s / 30s / 2min 重试。
2. **一个直播间固定一个会话**：插件声明一个双工消息网关，平台取直播平台（如 `bilibili`），群号取房间号。共享记忆组只认已存在的具体会话、不支持通配，每场一个新会话就得每场改配置，所以按房间固定。
3. **主播的话以麦麦身份"发"出**：观众消息经网关入站，带原始时间；主播发言由插件调 `send.text` 发进该会话，网关发送端不外发、只回成功，`send_service.after_build_message` 钩子把这条发言的时间改回原始时刻。这样会话里麦麦确实"说过话"，摘要按 MaiBot 原有规则触发，时间线也与直播一致。连续几句主播发言合并成一条，减少后续的模型调用。
4. **只收不说**：回放前把该会话的发言频率倍率设为 0，此时 MaiBot 只静默接收、不进规划器。网关发送端只认插件自己正在回放的发言，其余一律回失败——就算规划器想说话，也不会发出、不会入库。
5. **可续放、不重放**：插件把待回放记录和进度落到插件数据目录，插件或 MaiBot 重启后接着放；已放完的场次记下编号，重复推送直接忽略。
6. **需要用户改的 MaiBot 配置**（不改源码）：`adapter_policy.toml` 放行插件网关与房间号；`a_memorix.shared_memory_groups` 把直播间与要互通的 QQ 群、私聊编成一组（直播间会话在第一次回放后才存在）。

## 替代方案（Alternatives）

### 知识库导入流程

**暂不采用**。不触发发言、不建会话，最干净；但入口只在 WebUI，插件调不到，要么每场手动导，要么请维护者给插件开"创建导入任务"的能力。维护者若更倾向这条路，再换。

### 请维护者开放长期记忆写入接口

**不再提**。维护者倾向 namespace 方案；写入接口权限过高，不像该给普通插件的能力。

### 直播时实时送入

**暂不采用**。时间天然准确，但要求 MaiBot 全程在线，直播期间也要一直压住规划器；收播后整批回放加上改回原始时间，效果相同，且 MaiBot 当时不在线也能事后补。

### 主播的话也走网关入站（用麦麦的账号）

**拒绝**。入站消息不会触发聊天摘要，会话里永远没有"麦麦发出的消息"，整场记录都不会被总结。

### 回放时全部用当前时间

**拒绝**。实现最省事，但所有记忆的时间都落在收播后的几分钟里，"上周五几点播了什么"之类的问题会答错。

## 后果（Consequences）

- 直播间在 MaiBot 里是一个真实的群聊会话，WebUI 可查看；观众会登记为 MaiBot 的人物（平台为直播平台），之后能对常来的观众形成印象。
- 麦麦每发一条消息，MaiBot 都会对最近说话的人做一次人物事实提取（QQ 群里也是如此），一场回放下来会有几十到上百次模型调用；合并连续发言能压掉一部分。
- 摘要只在麦麦发言时触发：主播长时间不说话、其间弹幕超过 `chat_summary_writeback_context_length` 条时，多出的部分不进摘要。调大这个值能缓解，对 QQ 群同样生效。最后一句主播发言之后的弹幕，要到下一场回放时才会被总结。
- 插件新增的 `send_service.after_build_message` 钩子对 MaiBot 的每次发送都会触发；不是直播间会话时立即放行，但跨进程调用省不掉。
- 依赖 MaiBot 当前的摘要触发规则与发送钩子；这些规则改了，回放方式要跟着改。
