# ADR-045：直播近况推给 MaiBot（事实事件 + 出站上报器 + 插件侧注入）

- 状态：已采纳（2026-10-23）
- 日期：2026-10-23
- 实现提交：与本 ADR 同笔交付（`git log -- docs/decisions/045-live-status-sync-to-maibot.md`）；MaiBot 侧的接收、缓存与注入在 MaiBot-Amaidesu-Adapter 仓库

## 背景（Context）

MaiBot 7×24 常驻 QQ，Amaidesu 开播时才启动。两边定位为"一个身份、两个身体"：各自保有决策循环，不让 MaiBot 当主播的大脑（以 MaiBot 为决策核心的桥接早已放弃）。第一步已让主播经 MaiBot 上的适配器插件（MCP 工具）读写 QQ 群；反方向还缺一条：在 QQ 上和麦麦聊天时，它不知道自己"正在直播 / 刚播完一场"。

要同步的近况有四类：开播、换环节、收播、场次回顾。前三类已有事实事件（`live.started` / `rundown.changed` / `live.ended`）。场次回顾是收播后由后台调模型写成的，写完的时刻只有写入方知道，没有事件。

## 决策（Decision）

核心一句：**回顾写好补一条事实事件；一个只订阅事件、向外推送的上报器把近况推给适配器插件；插件缓存后在 MaiBot 每次规划与回复前注入，并提供查询工具。**

1. **新增 `streamer.recap.written`**：由 `SessionRecapWriter` 在回顾落库后发出（收播整理与启动补写共用 `write_recap`，两条路径都发），载荷带场次主键、起止时刻与回顾全文。场次主键由发布方显式填写——补写的是过去的场次，不能交给按"当前场次"盖章的拦截器。
2. **出站上报器 `src/modules/maibot_sync/`**：订阅上述四个事件，经 HTTP POST 推给插件（与 MCP 服务同一端口、同一令牌，路径 `/live-status`）。按组件判据它不是工具（不被调用）、不是 Agent（不持有办事过程）、也不是采集器（不采集数据），是与 StorageLedger 同形态的出站基础设施；放在 modules 下，与 VTS / Warudo / B 站等外部平台对接同位。配置为 infra.toml `[maibot_sync]`，默认关闭。
3. **推完整快照，不推增量**：每次都发"是否在播 + 场次信息 + 当前环节"的全量；直播期间按心跳间隔重发。插件错过任何一次都会被下一次补齐，也据心跳判断直播是否仍在进行。回顾单独推，失败按 5s / 30s / 2min 重试三次。模拟器回放场次不对外同步。
4. **插件侧**：缓存最近近况与若干场回顾并落盘；在 `maisaka.planner.before_request` 与 `maisaka.replyer.before_request` 两个钩子里，只在"正在直播 / 近期刚播完（时长可配置）/ 状态不明"时插入一段近况，位置在请求末尾每轮信息处，只写绝对时刻（不写"已播 N 分钟"），以免破坏前缀缓存；另提供查询直播近况的工具，Amaidesu 不在线也能答。

## 替代方案（Alternatives）

### 插件轮询 Amaidesu 的 Dashboard 接口

**拒绝**。插件需要知道 Amaidesu 的地址并依赖管理面接口；轮询有延迟；Amaidesu 不开时收播那一刻的回顾也读不到。近况是直播这边的事实，由事实发生方推送更直接。

### 上报做成 MCP 工具，复用现有 MCP 连接

**拒绝**。通用 MCP 的工具默认对主播可见，"上报"会混进 LLM 的工具列表；为藏它要么停用（调用也被拒），要么给 MCP 加隐藏机制——都是把"给 LLM 用的能力"和"代码通道"搅在一起。

### 上报器放进主播 Agent 内部、由主播直接调用

**拒绝**。开播 / 收播是场次管理器的事实，换环节与回顾才属于主播；按通道学说（ADR-031），事实通知走事件、消费方零耦合订阅即可，主播不需要知道有个 MaiBot 在听。代价只是补一条回顾事件。

### 只注入规划器，不注入回复生成

**拒绝**。回复生成只看得到规划器写下的想法，环节名、开播时刻若没被规划器转述，回复里就可能编错。多一次钩子调用的代价可接受。

## 后果（Consequences）

- 主播的近况在 QQ 侧可见；Amaidesu 不需要知道 MaiBot 的任何内部结构，只认插件的 `/live-status` 契约。
- 新增一条事实事件，日后其他消费方（如面板刷新回顾）可直接订阅。
- 直播中途重启 Amaidesu 不会重发 `live.started`：插件在心跳超时后把状态视为"不明"，直到下一次开播才恢复准确。
- MaiBot 的钩子每次都会把整份上下文跨进程传给插件，没有近况时处理函数立即返回，但这次传输省不掉。
- 插件钩子的注入格式依赖 MaiBot Context Item 协议（当前 schema 版本 1），协议升级时插件需同步。
