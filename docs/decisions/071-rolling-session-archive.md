# ADR-071：场次档案改为滚动快照（快照只引用原行 / 模型只挑不改写 / 超出上限按固定规则取舍 / 冷启动接住升级前几场）

- 状态：已采纳；修改 [ADR-066](066-memory-injection-switch.md) 第 1 条里"常驻简报带上一场的档案行"的含义——简报读上一场的档案快照，这一份里有那一场新写的事，也有从之前几场接住、仍然成立的事；三个读出口与两档写法不变
- 日期：2026-11-06
- 实现提交：与本 ADR 同批交付，按 subject 检索：`git log --grep "档案快照"`（存储、取舍、简报、整理面板、多场序列评测几笔）与 `git log --grep "整理对旧档案只挑不改写"`；也可 `git log -- docs/decisions/071-rolling-session-archive.md`

## 背景（Context）

ADR-066 起，常驻简报的档案段只取"最近一个已整理、有档案行的正式场"的档案，每份档案只写那一场的事。记忆视野因此只有一场：碰上一场短的、乱的，前面的事就全从简报里掉出去。实测一场直播开播时，简报里只有上一场写下的 7 行——那一场只播了十来分钟，中途崩了好几次；再往前那一场的事（召出女仆并取了名、女仆会自己捡东西、和观众一起定下的口味）一条都没有了，看起来就是"几乎全部失忆"。时长下限（`memory_brief_min_session_ms`）只挡得住开错后马上重开的那一两分钟。

要让前几场的事接下去，同时有三条约束：

- 旧的长期笔记就是一场又一场让模型把旧内容重写一遍，慢慢走了样。接下去的事不能再经模型转写；
- 删除路径都按档案行或场次走：记忆页删单行、复盘页按句删台词时连带删档案行（[ADR-067](067-irreversible-memory-cleanup.md)）、删观众时只在 ta 出现过的那几场里替换昵称（[ADR-068](068-memory-privacy-retention-and-forget.md)）。接下去的事不能躲开这些路径；
- 薄场不能把前面清空：一场又薄又乱的直播没聊到某件事，不等于那件事过时了。

## 决策（Decision）

核心一句：**每个整理过的正式场留一份档案快照，快照只引用原来的档案行；整理时模型对上一份快照逐行只挑不改写，代码按固定规则凑满至多 12 行；简报读上一场的快照。**

1. **快照只引用原行**：`archive_snapshots` 记哪些场次写过快照（快照可以是空的），`archive_snapshot_lines` 每行引用一条 `archive_lines`，另记位置、是否稳定的事、最近一次写下或再提起它的那一场的开播时刻。原行被删（删单行、按句删台词、改彩排、删场次）时外键级联从所有快照撤掉；删观众改的是原行文本，快照读到的也是替换后的；回想工具扫的是各场自己的档案行，遮名照旧。留下的行标题、原话、证据台词、出自哪一场、存档一个字节都不会变。
2. **模型只挑，不改写**：整理第一次调用多一段【上一份档案】，每行编号"旧N"。模型对旧行给三种操作，没列出的行一律保留：
   - 保留：可以写上本场又提起它的那一行（记为再提起），可以重标是否稳定的事。旧行里属于稳定的事、却没标稳定的，提示词要求逐行标上；
   - 去掉：理由必须以了结、不成立、记错、被取代四类之一开头，并指出本场哪一行台词是证据（代码核对它确实是本场播出的台词），"这场没提到""一次性的事"都不算理由。同一件事写了两行时，可以注明与哪一行重复去掉其中一行（事实由留下的那一行接着，留下的继承"稳定"；那一行本场被替换或去掉了，这一行跟着它走）；
   - 替换：新行按本场那一行台词写、原话照抄，过与新事同一个逐字引文校验器，通过才换掉旧行。

   不合规的操作不采纳、旧行照留，连同理由写进整理报告（WebUI 整理面板逐条列出）。
3. **薄场不能清空**：输出里没有对旧行的操作（或整个输出为空）时上一份原样保留；对旧行的操作不是列表、或上一份读不出来，都按整理失败处理、下次再试，上一份快照原样留着，简报照旧读它。
4. **超出上限按固定规则取舍**：一份快照至多 12 行（与简报档案行上限同一个数），按四档依次放：稳定的事至多 8 行（本场新写的在前，其余按最近被提起）→ 本场其余新事 → 其余稳定的事 → 其余旧行（按最近被提起）。同一档里挤出去的是最久没被再提的；前几场的零碎进展排在稳定的事后面。被挤出的本场新事照样写成本场档案行（回想工具查得到），只是不进快照。"稳定的事"只有四类：名字（给人、宠物、跟班、地点起的名字），住处在哪（家、据点、重生点），关系与伙伴（谁是她的什么人，以及跟班、宠物是什么样、会做什么——这些在游戏画面里看不出来），和观众一起定下的设定或梗；建造进度、摆了什么家具、种了什么、做了什么菜都不算，哪怕是在家里做的——这些标成稳定会占掉前 8 行，把前几场真正稳定的事挤出快照。整理提示词按这个先后挑新事，一次性小事靠后。
5. **重新整理的语义：每场留一份快照，不重放**：重新整理第 N 场时，第 N 场自己的档案行整份替换，第 N 场的快照从它之前最近一份快照重新算，第 N 场此前做过的去掉、替换随之作废。之后各场的快照不重放：第 N 场的旧行从它们里撤掉（外键级联），新行不进去。简报读最新一份，所以重新整理最近一场是精确的；重新整理更早的一场时，要让结果带到简报里，按时间顺序把它之后的场次依次重新整理。正式场改成彩排时，这一场的档案行（连同所有快照里对它们的引用）与它的快照一起撤掉；彩排改成正式后，下一次调度在它之前最近一份快照上整理它，同样不重放之后的场次。
6. **冷启动**：升级前整理过的场次没有存下的快照，由它自己的档案行加往前几场的档案行现拼（凑够两场时长不短于下限的就停、至多三场，遇到存下的快照接上它就停，同一句原话只留最新的一行）。存储升到 v28 时，如果库里还没有任何快照、而最近一个已结束的正式场已经按旧逻辑整理过，迁移把它放回待整理；启动补整理随即在现拼的基底上重新整理它。最近一场还没整理时不改，它的第一次整理就是这样滚的。两种情况都是启动时自动发生，不需要运维步骤。
7. **简报**：读上一场（最近一个整理过、时长够的场次）的快照，分两块列："上一场："下是那一场新写的，"之前："下是接住的；时间词仍只有"上一场""之前"，不写日期、天数、场次数。存档折叠与"不确定是哪个存档"的注明逐块照旧；档案行与承诺出自同一句台词时只留承诺那一条，接住的行同样适用。
8. **评测与门槛**：新增多场序列评测 `scripts/memory_eval/archive_rolling.py`，用例是"前一场立下稳定的事、中间夹着又薄又乱的短场、看最后还在不在快照里"，在真实库上跑生产整理器；发版门槛加五项：稳定的事遗忘率 ≤ 0.1、留下的旧行字节变化 0 处、删掉的误记行回来 0 条、没有本场证据的旧行被丢 0 条、进展被标成稳定的事 0 条。

## 替代方案（Alternatives）

### 简报读最近 N 场的档案拼起来

**拒绝**。被后来改写的状态（"还没点火"与"在烤了"同时出现）、已经了结的事都会原样回来，要在读侧再判一次哪条过时——那正是整理模型看着本场台词最适合做的判断。

### 把仍然成立的行复制进本场名下

最初实现过、同日改掉。副本带着"出自哪一场"一列，删场次、改彩排时能连带删，但删观众的昵称替换按"ta 出现过的场次"过滤，副本落在 ta 没来过的后面几场里，要每条删除路径都额外认副本；记忆页同一件事在好几场下重复出现；而且实现时模型可以把旧行改写成新行再写进来，重造了旧长期笔记那条层层转写的链。

### 让模型改写旧行的措辞

**拒绝**。理由同上：每场转写一遍，几场之后原话和意思都会漂；旧行只能原样留着或由本场原话替换。

### 只留一份"当前快照"，不分场次

**拒绝**。重新整理最近一场时撤不回它做过的去掉；也没法回到"上一份"作为重算的基底。每场一份快照至多 12 行引用，存储代价可以忽略。

### 重新整理较早的一场时自动重放之后各场

**暂不做**。每重整一场要按之后的场次数付整理调用，运营者点一次按钮可能触发一串模型调用；改为只重算这一场的快照，需要时由运营者按时间顺序依次重新整理。

### 只靠代码按"稳定"标记保留，不让模型判断

**拒绝**。"成立与否"要看这一场说了什么，代码判断不了；代码只做数量上的取舍。

## 后果（Consequences）

- 短场次不再把前面几场的事冲掉；遗忘只会发生在三处：模型给出带本场证据的去掉或替换、超出上限按固定规则挤出、运营者删除。三处都写进整理报告或由运营者自己操作。
- 常驻简报的档案段上限从 8 行变成 12 行。全部字段写满的最坏情况实测 3,483 cl100k token（同样写满的 8 行版本为 2,640，增加约三成）；贴近真实长度的 12 行加 1 条承诺约 1.2k。整理时交给模型的旧行清单 12 行写满约 2.9k，冷启动时至多 24 行约 5.8k。
- 稳定的事超过 8 件后开始互相挤占，最久没被再提的先出；这时她靠回想工具查更早的档案。
- 重新整理较早的一场不会连带重算之后各场，见决策第 5 条。
- 档案提示词升到 1.6，属于提示词改动，按发版门槛要过 live 评测；多场序列评测只用本机整理模型跑过，没有评估采样方差。
