# ADR-071：场次档案改为滚动累积（整理时接住上一份仍然成立的事 / 长期的事先占位 / 简报分上一场与之前几场）

- 状态：已采纳；修改 [ADR-066](066-memory-injection-switch.md) 第 1 条里"常驻简报带上一场的档案行"的含义——简报仍只读最近一份档案，但这一份不再只有那一场的事；三个读出口与两档写法不变
- 日期：2026-11-06
- 实现提交：与本 ADR 同批交付，按 subject 检索：`git log --grep "档案行记下出自哪一场"`、`--grep "下播整理把档案滚着记"`、`--grep "简报分上一场与之前几场"`；也可 `git log -- docs/decisions/071-rolling-session-archive.md`

## 背景（Context）

ADR-066 起，常驻简报的档案段只取"最近一个已整理、有档案行的正式场"的档案，每份档案只写那一场的事。这样记忆视野只有一场：碰上一场短的、乱的，前面的事就全从简报里掉出去。实测一场直播开播时，简报里只有上一场（一场只播了十来分钟、中途崩了好几次的短场）写下的 7 行；再往前那一场的事——召出女仆并取了名、女仆会自己捡东西、和观众一起定下的口味、被玩家偷袭过几次——一条都没有了，看起来就是"几乎全部失忆"。

时长下限（`memory_brief_min_session_ms`）只挡得住开错后马上重开的那一两分钟，挡不住这种十来分钟的短场；把简报改成读最近几场的档案拼起来，又会把已经了结、被后来改写的旧事（"炉子还没点火"）原样带回来。

## 决策（Decision）

核心一句：**每次下播整理把上一份档案交给整理模型，仍然成立的接过来、被这一场改写的重写、了结或过时的去掉，再加上这一场的新事，写成这一场的档案；简报照旧只读最近一份。**

1. **接住**：整理第一次调用（写档案）多一段【上一份档案】，每行编号"旧N"，注明出自上一场还是更早、原话、在哪个游戏哪个存档、是否长期。模型在 `keep` 里列出仍然成立的旧行编号；这一场有了新进展的不留旧行，按这一场的原话写新行（新行照旧要逐字引文）；明确了结、不成立或被取代的不列；拿不准的留。上一份档案取开播早于本场的最近一份正式场档案，不看时长（滚动档案本身就带着前面的事）。
2. **长期的事先占位**：名字、关系、住处与家当、和观众一起定下的设定标 `lasting`。一份档案至多 12 行：长期的事先占至多 6 行（接过来的在前、本场新写的在后）→ 本场新事（至多 8 行）→ 接过来的其余行。长期的事因此不会被一场里的新事挤掉，又不至于把新事全挤出去；占位装不下的长期新事仍按新事排。
3. **接过来的行保留出处**：原话、证据台词、游戏、存档照旧，另记这件事出自哪一场（`from_session_id`）和是否长期（`lasting`）。存储升到 v27，存量行这两列留空，即"滚动之前的旧行"。
4. **开始滚动的第一场**：上一份还是滚动之前的旧档案时，往前再取几份旧档案一起交给模型（至多 3 份，遇到滚动档案为止）。升级前最后一场如果正是一场短的、乱的，更早的事也能接上。
5. **读侧**：简报分两块——"上一场："是那一场新写的，"之前几场还记着的事："是接过来、仍然成立的；存档折叠与"不确定是哪个存档"的注明逐行照旧。回想工具扫档案时同一句原话只给一条，时间按最初说它的那一场标。
6. **兜底**：模型输出里没有 `keep` 这个键时，上一份原样接住（宁可多带几行，也不因格式出岔子全忘）；`keep` 不是列表、上一份读不到，都按整理失败处理、下次再试，不写一份顶掉前几场的档案。
7. **删与改跟着副本走**：场次改成彩排、删除场次时，连同接进后面几场、出自它的副本一起删；删观众时副本里的昵称一并替换；重新整理某一场只替换它自己的档案，不动它此前接进后面几场的行。

## 替代方案（Alternatives）

### 简报读最近 N 场的档案拼起来

**拒绝**。旧事原样带回：被后来改写的状态（"还没点火"与"在烤了"同时出现）、已经了结的事都会回来，要在读侧再判一次哪条过时——那正是整理模型看着本场台词最适合做的判断。

### 只靠代码按"长期"标记保留，不让模型判断仍然成立

**拒绝**。"成立与否"要看这一场说了什么，代码判断不了；只靠标记会把被改写的长期事实（住处搬了）也一直留着。代码只做数量取舍。

### 另起一张"长期事实"表

**拒绝**。多一种记忆就多一个出场入口和一套纠错面；长期事实和场次档案出自同一类台词、同一次整理，放在同一份档案里用 `lasting` 区分，运营者在记忆页删一行就够了。

## 后果（Consequences）

- 短场次不再把前面几场的事冲掉；简报从"一场的视野"变成"一份滚动档案的视野"（至多 12 行）。
- 档案行会在好几场的档案里重复出现：记忆页按场次看到的是每一份滚动档案；运营者要纠正一件事，删最新那一份里的那一行（更早几份里的副本不再被接过来，只留在回想里，回想按原话去重）。
- 整理第一次调用的输入多了上一份档案（至多 24 行），用量略增；在一份真实直播库副本上整理一场直播，三次调用合计约 2.6 万到 2.9 万 token。
- 档案提示词升到 1.2，属于提示词改动，按发版门槛要过 live 评测；现有档案挂游戏评测只覆盖新事挂哪个游戏，不量 keep 判得准不准。
- 重新整理较早的一场不会连带重算它后面的场次；要让后面的档案跟上，按时间顺序依次重新整理。
