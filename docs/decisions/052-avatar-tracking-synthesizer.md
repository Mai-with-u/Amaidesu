# ADR-052：虚拟形象由面捕合成器逐帧驱动（平台适配器缩成驱动 / 表情跟着播放起落 / VTS 先行）

- 状态：已采纳；部分取代 ADR-023（"自动情绪路径 = 每个适配器订阅发言并各自翻译成平台参数"一条，对已移植到面捕合成器的平台不再成立）与 ADR-026（VTS 的 `set_expression` 落地方式；工具名与参数形状不变）
- 日期：2026-10-29
- 实现提交：可用 `git log --grep` 按 subject 检索——`feat(avatar): 面捕合成器的通用通道与反射行为`、`feat(avatar): 表情配方与带时间曲线的调度`、`feat(avatar): 面捕合成器逐帧合成与事件运行时`、`feat(avatar): VTS 改由面捕合成器逐帧驱动`

## 背景（Context）

ADR-023 让每个平台适配器订阅 `streamer.speech`，把每句话的情绪标签查表成一组平台参数写一次。这条路在 VTS 上暴露出几个结构性问题（读代码与本机实测得出）：

- **几路互相覆盖**：表情、口型渲染器、待机微动三路都写 `MouthSmile`。待机微动在不说话时每 40 毫秒强制写一次基线，口型渲染器在开口时也写一次基线、停顿时写 0，情绪里的嘴角几乎显示不出来。
- **时间对不上**：发言事件在送进 TTS 合成之前发出，表情一出就上脸，比声音早一个合成时长。
- **没有起落**：每次查表都是同一张脸、一步到位；不说话、思考、看弹幕的时间里，形象只剩随机微动。
- **停注入不回落**：实测 VTS 1.35.10 在没开摄像头面捕时，停止注入 10 秒后值仍保持；程序中途退出时，形象会停在最后一帧，比如半闭眼。
- **锁步收发慢**：pyvts 的请求是"发一条、等下一条消息当回复"，只能一把锁串行。实测 VTS 每渲染一帧（本机约 28 帧/秒）才处理一次排队请求，所以锁步时每条请求都白等一帧；连发不等回复，10 条的回复在 37 毫秒内全部回来，顺序还会乱。

从第一性原理看，真人主播的形象自然，是因为面捕软件每秒送来几十帧完整的脸，呼吸、眨眼、眼神、表情起落同时在发生。AI 主播背后没有这个人，缺的是"一个持续运行、任何时刻都能给出整张脸的过程"，而不是更准的情绪标签。所以只给情绪映射加节奏补丁不够。

## 决策（Decision）

**在形象模块里新增面捕合成器（`src/modules/avatar/tracking/`），作为替代摄像头的面部捕捉数据来源；平台适配器缩成驱动，只负责把每一帧写成本平台的输入。**

- **通用通道**：每帧是一组平台无关的身体参数，包括头部三轴角度、左右眼开合与睁大、视线、左右眉、嘴角、张嘴、嘴歪、鼓腮、生气。每个通道都有取值范围和每秒变化上限，任何来源都写不出界，也不会瞬移。
- **按时间尺度分工**：
  - LLM 只给每句话的态度，也就是情绪标签加强度，词表不变；
  - 眨眼（频率随说话与否变化、闭合快睁开慢）、眼神微动、头部漫步、表情起落都由合成器按规则生成；
  - 随机源可注入，同一个种子得到同一串输出。
- **情绪标签展开成配方**：每个标签的配方同时作用在脸、眼神、头部上，并能收放头部微动的幅度。配方按族决定浮现与回落的快慢。调度规则如下：
  - 同族、强度相近：只延长当前表情，不重来；
  - 换别的表情：当前表情至少停留够最短时长，否则排队；
  - 排队期间那句话已经播完：作废；
  - 惊吓族、强度不低于 0.6：可以打断；
  - 给定强度先压缩，说话时的表情大多是淡的。
- **表情跟着播放走**：
  - 开着 TTS 时，发言事件只把情绪记下，`tts.utterance.started` 时表情才浮现，`finished` 后再停留一会儿回落，`failed` 就作废；
  - 没开 TTS 时，按字数估算这句话说多久；
  - 口型分析器的信号经一个只记数值的渲染器接入：说话时下巴开合只听口型，嘴角仍归表情。
- **一个合成器、多个驱动**：
  - 组合根构造一个合成器（调参在 `avatar.toml [tracking]`），经 `bind_core_tools` 交给 avatar 平台；
  - 平台把驱动挂上去，有驱动时才跑帧循环；
  - 摘下驱动和关停时，先发一帧静止姿态。
- **VTS 先行**：
  - VTS 驱动每帧整组注入一次捕捉输入，由模型作者调好的映射曲线换成模型参数；
  - "正常睁眼 / 中性嘴角 / 中性眉"对应的输入值是逐模型的校准项，在 `[platform.vts]` 配置；
  - 连接与换模时读一次输入范围，按范围钳制，只发 VTS 认识的输入；
  - 连接改用自带客户端，后台按 `requestID` 对回复，逐帧注入发完就走，pyvts 依赖移除；
  - 待机微动、常驻微笑基线、情绪表、口型渲染器随之退役；`avatar.toml` 升 2.0.42，"关过待机微动"这一意图迁移为 `[tracking].head_wander_enabled = false`。
- **工具面不变**：`vts_set_expression` 交给合成器，保持配置时长后回落；`vts_set_idle_enabled` 开关头部漫步；调试台写参数改为临时覆盖 3 秒。
- **其他平台暂缓**：Warudo、VRChat、表情差分图仍走 ADR-023 的情绪订阅，等有可用模型再移植。
- **主播包零改动**：主播 Agent 仍只发事实事件，对平台零感知的验收照旧。

## 替代方案（Alternatives）

- **在各适配器里各加一层表情节奏**（保持、回落、最短停留、渐变）：能缓解切换频繁，但不解决几路互相覆盖、不说话时没有身体过程、每个平台重复实现这几件事；被否决。
- **只用 VTS 原生表情文件（自带 0~2 秒淡入淡出）承载情绪**：作者做好的整套表情效果好，但表情是开关式的，表达不了眨眼、眼神、头部这些连续过程，而且依赖每个模型都配齐表情文件。保留为风格化标记与动作片段的后续通道，不作主路径。
- **学习式音频驱动面部（如 NVIDIA Audio2Face，2025 年 9 月开源）**：自然度上限可能更高，但按写实人脸训练，用在动漫模型上效果未知；要和 GPT-SoVITS 抢显卡；模型权重是 NVIDIA 自己的模型许可。规则版跑通后可作为"说话时的面部"一层的可选来源再评估。
- **每个平台各自持有一个合成器**：多形象时各演各的，状态不一致；被否决，组合根只建一个。
- **继续用 pyvts 加锁**：锁步时每条请求白等一帧，帧循环和热键、探活互相拖慢；被否决。

## 后果（Consequences）

- 形象有了连续的身体过程：会眨眼、有眼神微动、表情跟声音起落；同一帧只有一个来源写参数，覆盖问题在结构上消失。
- 离线回放（`scripts/avatar_tracking_replay.py`）可以拿事件历史日志逐帧推进合成器，输出曲线图与指标：发言到开播的间隔、表情每分钟切换次数、分状态眨眼频率、最长冻住时长。不开 VTS 也能调参数。
- 代价：
  - 风险集中在合成器：它出缺陷就是整张脸出问题（有日志与静止姿态收尾兜底）；
  - 合成器接管全部捕捉输入后，不能和真人面捕同时用（VTS 的叠加注入模式留作以后共存的出路）；
  - 规则的自然度有上限，调参要靠人眼；
  - 模型作者做的、通道组合不出来的效果，要靠后续的风格化标记与自建输入补；
  - 校准项要逐模型调。
- 情绪由每个适配器订阅反射的写法只剩未移植的平台在用；全部移植后 `speech_binding` 可退役。
