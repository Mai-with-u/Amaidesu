# ADR-075：游戏里的人按 UUID 认（玩家表放 Amaidesu / 只自动记她亲身经历的互动 / 对某位玩家的承诺按两条证据路径核对 / 玩家与观众对号由运营者确认且永不告诉她 / 删玩家与公屏"忘了我"）

## 背景（Context）

她在 Minecraft 里会遇到别的玩家：打招呼、扔东西给她、找她切磋、在公屏和她聊天。Mod 收到的每条玩家聊天都带发言人 UUID，并核对过是不是此刻在线的那个玩家；别人冲她做肢体动作的事件也带玩家 UUID。可 Amaidesu 这边原先只把这些读成一句话放进本场时间线：公屏聊天不落库，UUID 没往下传。到了下一场，她一个玩家都不认得，对来过几场的人也说"初次见面"。

承诺的"对谁"原先只有全体与某位观众两种。对某位观众时代码要求那一行台词在回应一条弹幕，所以在游戏里答应玩家的事，要么被登记成对全体、在没有他的场次里被反复提醒，要么被丢掉。

和"不存观众的往事与画像"那条边界的关系：这里记的是她自己经历过、直播画面里看得到的互动，不是这个人的往事与画像；玩家说他自己的事，和观众定下的事同一个口径，要人批准（[ADR-074](074-viewer-defined-memory-needs-approval.md)）。

## 决策（Decision）

核心一句：**按 UUID 认玩家，只自动记和她发生过的互动；他开口或冲她做动作时推一张"这位是谁、和你有过什么"的卡；答应他的事按她自己说出去的话核对对象；玩家和观众不自动对号。**

1. **认人**：玩家表 `game_players` 放在 Amaidesu 的库里（存储 v32）：游戏、UUID、最近一次的名字、见过的名字、首次与最近一次见到的场次与时刻、见过的存档。只认带 UUID 且核对过在线的发言人：没有 UUID 的、在线核对不过的（控制台、命令方块借了个名字）不建玩家、不记互动。同一个 UUID 改了名仍是同一个人，卡片写"以前叫"；同名不同 UUID 是两个人。
2. **自动记什么**：打招呼（冲她蹲起、挥手、拍一下，一场合并成一行）、送东西（朝她扔东西）、切磋（谁赢、各打中几下）。来自游戏 Agent 发的 `game.player.interacted` 事件，只落库，主播不订阅、不进她的对话时间线。不记私聊、玩家之间的事、玩家说的关于他自己的事。公屏聊天落进 `game_chat`（玩家说的挂玩家；她说的取自她发言动作的结果；认不出是谁说的只占一行位置、不存原话），和弹幕一样受保留期管，私聊不落库。场次改成彩排时撤掉本场的互动。
3. **她怎么用上**：不进常驻简报（12 行留给她自己的事）。本窗在公屏开口、或冲她做动作的玩家，以前在正式场里和她有过往来的，推一张玩家卡：打过几次招呼、送过什么、切磋输赢，现在的名字与以前的名字，答应过他、还没了结的事（至多两条）。卡只推给这一窗找过她的那几位，按 UUID 对上，不会推错人；同一位每场至多两次、隔十分钟，她本场已经回应过他就不再推。卡面不写上线时间、私聊、没批准的自述。卡只给主播的 Planner，**不给游戏 Agent**：游戏 Agent 要不要因为"老朋友"改变待人方式，是游戏行为的改变，另写规格、单独请示。
4. **对某位玩家的承诺**：`commitments` 加对象玩家与公屏证据两列。证据二选一，都必须是她自己说出去的：
   - 她播出的那句台词，而且落库时记下了在回应这位玩家（那一窗新到的游戏聊天只来自他一位时才记）；
   - 她在游戏公屏打出去的那句：点了他现在或以前的名字（不分大小写，单字名不算），或在他上一句之后 3 句之内、中间只有她自己的话（认不出是谁的一句也算插话）。

   模型写的"对谁"必须按上面两条之一对上那位玩家，对不上的不登记、进整理报告的未登记清单。公屏上打的字只登记对某位玩家的承诺：她在公屏冲所有人说的，看不出对哪位玩家，也不是播给观众的台词，不登记。对玩家的承诺和对观众的承诺一样不进常驻简报、游戏卡和回想工具，只写在他的玩家卡上。
5. **玩家与观众对号**：不自动对号，同名、名字像、同时出现都不算。记忆页"游戏里的人"给运营者一个确认入口，确认后记一行关联（观众、玩家、确认时刻）。关联只用来连带删除、让运营者看清楚，**永远不告诉她**，也没有"可以告诉她"的开关：跨平台对号是隐私风险，收益小。
6. **删除**：
   - 删玩家（记忆页入口）：他的互动、公屏聊天、对他的承诺随外键一起删；她的台词、档案、承诺、游戏事件和她在公屏打的字里他的名字（含以前的名字）换成"一位玩家"；UUID 的摘要进不记录名单（与观众同一套摘要，种类按游戏区分），之后他再出现也不再记，他的话只占一行位置。在这里删玩家不动关联的观众；
   - 删观众、观众"忘了我"：连带删运营者确认过关联的玩家；
   - 玩家在公屏打"忘了我"也算：和观众同一套口令、同一个宽限期，立即停止记录，宽限期内撤回就恢复；到期删除时连带删确认过关联的观众。宽限期里不推他的卡，按名字对的切磋不算他。
7. **整理怎么看**：找承诺那次调用的原料多两段：【游戏里的玩家】（本场代号"玩家1、玩家2"与名字）与【你在游戏公屏打出去的字（前面附着玩家说的话）】（她打的每一句编号"公屏#N"，连同前面 3 句）；台词里回应玩家的那一句标"（回应玩家N）"。找承诺提示词升到 1.3。

## 替代方案（Alternatives）

### 玩家表放在 MaiCraft 那边

**拒绝**。玩家记忆只给主播，删除、遗忘、保留期都在 Amaidesu 的存储侧；放在 Mod 那边就要两边各删一遍。

### 玩家进常驻简报

**拒绝**。简报 12 行留给她自己的事；玩家只在他露面时才相关，走线索卡。

### 同名自动对号到观众

**拒绝**。同名常见，对错了就把 A 的事安到 B 头上，还会把直播间身份和游戏身份当众连起来。

### 公屏上冲所有人说的也登记成对全体的承诺

**未采纳**。公屏的字观众不一定看得到，也不是播出去的台词；对全体的承诺仍只从她播出的台词里找。

## 后果（Consequences）

- 老玩家又来了，她会被提醒"上次送过你面包、切磋你赢了"；答应玩家的事他再露面时被提醒，不再在没有他的场次里反复提。他不在就不提。
- 风险：离线模式服务器的 UUID 由名字算出，那种服上认人只能做到认名字，两个人轮流用一个名字会被当成同一个人；改名后她可能叫旧名字；换小号对她来说就是陌生人。
- 还没做的：玩家说他自己的事（列待审候选的表已建，整理还不生成，要改档案提示词并加评测）；一起做的事、帮过忙两类互动；她在台词或公屏回应玩家时记一次打招呼；整理报告里本场新认的玩家数与互动条数。切磋只在按名字点了对手时记（Mod 的切磋结果不带对手 UUID）；旧版 Mod 不报在线核对，玩家不会被建档；测试服把玩家聊天当系统消息发，同样建不了档。
- 删玩家的残留边界：游戏生物名册里的名字与主人名不替换（名册跨场次，游戏每次照原样报回），与删观众同一口径，写进运维手册。
- 要 Mod 补的字段（单独向 MaiCraft 提）：切磋结果带对手 UUID、跟随状态带玩家 UUID、服务器是不是在线模式。
