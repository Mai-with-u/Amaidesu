# ADR-043：游戏 Agent 的两种交互形态——主播侧按工具面说明拼装玩法

- 状态：已采纳（2026-10-15）
- 日期：2026-10-15
- 实现提交：与本 ADR 同笔交付（`git log -- docs/decisions/043-game-agent-interaction-shapes.md`）

## 背景（Context）

三分判据把 minecraft、text_adv、game_2048 都判为游戏 Agent（命令驱动），判据明确不要求 LLM。但主播与游戏之间其实存在两种交互形态：

- **委派型**（minecraft）：主播用"目标"说话，分钟级；游戏侧自带 LLM 拆解动作。需要 `framework_delegate` / `framework_prompt` / 任务账本 / `game.report` 整套。
- **遥控型**（text_adv、game_2048）：主播用"动作"说话，一次按键或一次选择；游戏侧零 LLM，只有规则引擎加可选的感知循环。只需要工具加事件，不需要账本。

机制层本已两者都撑得住：BaseAgent 默认拒收委派、委派名册按是否覆写接收入口探测、工具可见名单、`game.*` 事件、【现场速览】按配置的工具名读取。但主播侧与框架接缝只认委派型：Planner 提示词通篇教 `framework_delegate`，没提直接调游戏工具；观众命令路由硬接 `framework_delegate`；留空目标在全体名册里解析，遥控型 Agent 同时启用会被算成歧义候选；没有任何地方告诉主播"这款游戏该怎么玩"。只启用 2048 时，模型会先去委派、被拒收后自己猜该调什么。

## 决策（Decision）

1. **工具面自带使用说明**：`BaseToolProvider.guide_for(agent_name)` 默认空串；`ToolRegistry.guides(for_agent)` 按可见名单收集 `(提供者名, 说明)`。游戏 Agent 在自己的工具面上声明这款游戏是委派型还是遥控型、该调哪些工具；框架的委派工具面只在有能接收委派的 Agent 时才给说明（读者自己不算候选）。
2. **主播提示词按说明拼装**：主模板增加【当前游戏的玩法】段（`game_rules` 变量），Planner 每个决策窗把说明拼成该段；framework 工具面给出说明时追加委派型守则子模板 `amaidesu_planner_delegate_rules`（原来写死在主模板里的开始做事 / 补充要求 / 完成口径 / 游戏里的聊天守则整段搬入）。没有任何说明时明说没有游戏，模型不对不存在的游戏工具硬凑动作。
3. **观众命令两张映射表**：`mappings`（命令 → 自然语言指令，走委派）与 `tool_mappings`（命令 → 固定工具调用，经注册表直调；参数写死、观众输入不透传）。同名以后者为准，两表合起来即白名单。
4. **留空目标只认可接收名册**：`framework_delegate` / `framework_prompt` 的留空目标只在覆写了对应接收入口的 Agent 里解析；没有候选时错误信息指明"直接用它自己的操作工具"。
5. **不给遥控型 Agent 补假的 `receive_delegation`**：2048 收到"帮我合成 2048"只能靠策略代打，违背它"AI 代打等于开挂"的设计；text_adv 的选择是主播人设的一部分，不可委托。

## 替代方案（Alternatives）

- **给 BaseAgent 加玩法说明类属性，让主播持有 AgentManager 引用来读名册**：否决。主播侧已经只从工具注册表读工具面，说明跟着工具走不需要新接线；Agent 级声明会让主播依赖名册对象，而可见名单本就在注册表里，说明与名单同源。
- **用 Agent 分类层（`[agents.game]` + 形态字段）表达形态**：ADR-018 已否决分类层；形态由"工具面说明 + 是否覆写接收入口"自然表达，无需配置再说一遍。
- **让遥控型 Agent 实现 `receive_delegation` 把自然语言翻译成按键**：否决，见决策 5。
- **委派守则留在主模板，只加一句"没有委派时忽略"**：否决。模型看见 `framework_delegate` 工具与整页委派守则时仍会去试，被拒收后才回头，白费一步推理还可能说错话。

## 后果（Consequences）

- 换游戏只改 `agents.enabled`（遥控型按需加 `tool_mappings`），主播提示词的玩法段自动跟着换；框架与主播侧仍不出现任何游戏名（ADR-018 保持）。
- 新增游戏 Agent 多一条登记：工具面覆写 `guide_for`。不写则主播只看到工具的逐条 description，没有形态级说明。
- 委派守则子模板只在委派型游戏在场时注入，无游戏或纯遥控型直播省下这段上下文。
- 遥控型游戏的观众命令直接触达工具，主播只经游戏事件得知结果，没有"观众刚才按了什么"的通道；要让主播播报观众指挥，后续再议时间线记录。
- 工具注册表多了一个与提示词相关的职责（收集说明）。接受：说明与可见名单同源，放在别处反而要再查一次名单。
