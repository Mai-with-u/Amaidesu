# ADR-067：清掉旧记忆的存储面（删三处旧结构 / 删库文件旁的旧笔记目录 / 复盘页可按句删除）

- 状态：已采纳；取代 [ADR-066](066-memory-injection-switch.md) 的"旧表与旧文件原样保留，清理由后续提交做"一条，并补齐合规最小集里缺失的"删除单句"能力
- 日期：2026-11-04
- 实现提交：与本篇同笔交付，`git log -- docs/decisions/067-irreversible-memory-cleanup.md` 可检索

## 背景（Context）

ADR-066 把注入切到承诺账本与场次档案，旧的场次回顾（`session_recaps`）、观众画像（`viewer_profiles`）与本场备忘录（`live_sessions.notebook_text`）随之停写，但结构原样留着等阶段 4 清理。留着它们有三个实际代价：

1. **隐私面收不干净**。旧长期笔记除表之外还在库文件旁写过 `memory/MEMORY.md`、`MEMORY.rehearsal.md` 与 `memory/history/` 历史留底，正文里有观众昵称。表里那一行删得掉，这些文件没有删除入口，观众发"忘了我"之后仍然留在磁盘上。
2. **每处删除与迁移都要为死数据付账**。观众删除函数要继续擦旧表与旧文件，身份合并要照顾 `viewer_profiles`，升级链要维护两张没人写的表的建表语句；`viewer_profiles` 在合并路径上还留着裸 SQL，表一删就 500。
3. **合规最小集缺一项**。运营者能删一条承诺、删一行档案、删整场，但没有"删她说的某一句话"：被诱导说出口的一句、说漏的观众私事，只能连整场一起删。这是硬要求，不能留到以后。

## 决策（Decision）

核心一句：**旧记忆的存储面整批退役——v25 迁移删两张表与 `notebook_text` 列、删库文件旁的 `memory/` 目录；同一版补上"删除单句"的存储原语与 WebUI 入口。**

1. **v25 迁移（不可逆）**：`DROP TABLE session_recaps`、`DROP TABLE viewer_profiles`、`ALTER TABLE live_sessions DROP COLUMN notebook_text`；随后删除库文件同级的 `memory/` 目录。全部做存在性检查，重复执行安全。v18 迁移里重建 `viewer_profiles` 的建表语句冻结在 v18 文件内，历史升级链不依赖当前 schema。
2. **删除单句**：`DELETE /api/v1/review/speech/{chat_id}` 在同一个事务里删这句台词、删引用它的档案行、清空引用它的承诺的原话（承诺行保留）；复盘页加"本场台词"面板，逐句可删。
3. **旧画像与旧回顾的读取面一起删**：复盘聚合不再读收播回顾，回忆合并路径不再碰 `viewer_profiles`，WebUI 复盘页去掉"收播总结"面板；`/api/v1/agents/{name}/memo` 只剩有备忘录的 Agent。
4. **配置键同批退役**：`[agents.streamer.memory]` 与 `[maibot_sync].share_notes` 由各自文件钩子删除（版本链上界下一位：agents.toml 2.0.51、infra.toml 2.0.45）。`[maibot_sync].send_recap` 一并删：回顾已不存在，这个开关没有任何消费者，留着只会变成"改了没反应"的空旋钮（偏离精简方案 6.3 节只列 `share_notes` 一处，理由记在此）。
5. **不可逆的前提是备份**：迁移前的库备份保留（保留期清理不删 `*-pre-v*.db`），回滚靠它；删掉的表与文件不提供导出。

## 替代方案（Alternatives）

### 保留两张表只读，界面标"已停用"

**拒绝**。死表没有读者，却要继续被观众删除函数、身份合并与升级链照顾；隐私删除要擦一块没人看的数据，出错的概率反而更高。

### 只删表、不删 `memory/` 目录

**拒绝**。表里那一行删掉了，含同样昵称的笔记正文与历史留底还在磁盘上，观众删除请求名义上执行了、实际没执行完；这个目录也没有别的读取方，留它只有隐私成本。

### 旧表暂留，等以后攒够数据再决定

**拒绝**。旧结构已经停写半年也会一直是"待清理"状态，每加一个新功能都要在删除函数里记得它；而且旧回顾与画像的注入面已经切掉，留着的唯一作用是被误读。

### 把"删除单句"放到下一版

**拒绝**。这是合规最小集里的必做项，且与旧表清理同属"删得掉"的能力；拆开交付会让阶段的验收标准落空。

## 后果（Consequence）

- 升级不可逆：v25 之后旧回顾、旧画像与本场备忘录在库里不存在，`memory/` 目录被删；要找回只能用升级前的备份。
- 观众删除函数的覆盖面收窄为真实在用的表（观众、曾用名、弹幕、承诺、付费三表、话题摘要、档案行），旧画像与旧笔记不再需要逐处擦洗。
- 复盘页多一块"本场台词"面板与按句删除；删除一句会连带删掉引用它的档案行，对它的承诺保留但原话清空，界面上显示"原句已删除"。
- 升级后第一次启动不能再回退到旧版本二进制：旧二进制不认识 v25，会把两张表按建库语句重建出来并与账本口径分叉。
- 与 MaiBot 的回顾推送、共享笔记同步彻底没有配置入口；要给 MaiBot 发什么由使用者另行决定，不在本决策范围内。
