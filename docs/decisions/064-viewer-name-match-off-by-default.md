# ADR-064：按昵称关联观众默认关（部分取代 ADR-047 的自动关联默认：时限默认 0 / 同名一律转待确认 / 想要自动关联的人自己把天数调回来）

- 状态：已采纳；部分取代 [ADR-047](047-viewer-identity-mapping.md) 第 3 条"恰好一个候选且在时限内就自动关联"的默认行为，以及"时限默认 90 天"的取值；ADR-047 的同行存两种 ID、候选判定、改名、合并与取消关联等其余部分不变
- 日期：2026-11-03
- 实现提交：与本篇同笔交付，`git log -- docs/decisions/064-viewer-name-match-off-by-default.md` 可检索

## 背景（Context）

ADR-047 让新出现的观众 ID 在同平台内按昵称精确匹配老观众：同名候选恰好一个、且这个昵称在时限内出现过，就把新 ID 直接写进老观众那一行，视为同一个人；时限做成 `storage.toml` 的 `[viewers].name_match_window_days`，默认 90 天。当时考虑的风险是"改名后旧名字被别人拿走"，用时限挡：昵称很久没出现才转人工。

时限挡不住有意的冒充。B 站昵称由用户自己改，一个人只要把新号改成某位老观众正在用的名字，再用一个这边没见过的 ID 发言（例如老观众走 LAPLACE 源、冒充者走官方开放平台源，或者反过来），就满足"同名唯一候选、昵称最近出现过"，会被直接并进老观众：老观众的长期印象、答应过的事、贡献统计都会被主播当成这位冒充者的。关联发生在后台，主播与运营者在合并前看不到任何提示，事后只能在档案页发现并取消关联，而这期间主播已经按老观众的身份跟冒充者说过话了。昵称是任何人都能填的字段，用它自动认人，等于把认人的决定交给了来发言的人。

另一层顾虑来自平台规则：B 站开放平台的管理规范对用户数据的使用有约束，把不同来源的身份按昵称串起来是否属于协议不允许的用法，目前没有定论，这里只记作"可能有冲突"，不当成已确认的事实；即便不考虑协议，上面的冒充风险也足以改默认。

## 决策（Decision）

核心一句：**按昵称自动关联改为默认关：`name_match_window_days` 默认 0，0 表示永不自动关联；同名的新观众 ID 一律先建新观众并挂一条待确认的合并建议，由运营者在 WebUI 待确认页确认。配置键保留，填大于 0 的天数即恢复 ADR-047 的时限内自动关联。**

1. **默认值与取值范围**：`[viewers].name_match_window_days` 默认 0，下限从 1 放宽到 0。
2. **0 的语义**：关联判定先看时限是否大于 0，为 0 时即使同名候选唯一、昵称刚刚出现过，也不写进老观众那一行，而是新建观众、`link_status=pending`、`link_candidate_id` 指向这位候选。候选不止一个、没有候选、占位昵称跳过等其余分支与 ADR-047 相同。
3. **存量配置迁移**：`storage.toml` 升到 2.0.41，升级钩子只在值恰好等于旧默认 90 时改成 0，其他天数（包括用户显式填的 30、180）原样保留；改写时打一条警告日志，说明为什么改、以及"如果 90 是你有意设的，请改回"。缺这个键的文件按新默认补 0。

## 替代方案（Alternatives）

### 保持默认 90 天，只在文档里提示冒充风险

**拒绝**。风险由默认值带来，绝大多数运营者不会去读这条提示；冒充一旦成功，主播会当场把老观众的私事讲给冒充者听，事后取消关联收不回已经说出口的话。

### 删掉配置键与按昵称关联的代码

**拒绝**。只用一个数据源、或者能接受这个风险的运营者，仍然可能想要换源后老观众自动接上；保留配置键的成本只有一个判断分支，删掉则这部分人没有办法再打开。

### 时限内自动关联、但给主播加一句提示"这位可能是新号"

**拒绝**。提示只能让主播措辞更谨慎，关联本身已经发生，老观众的记忆已经注入给冒充者；要防的是注入，而不是措辞。

ADR-047 曾以"一律人工则每次换数据源都会把所有回访观众塞进待确认队列"为由拒绝"一律人工确认"。本篇接受这个代价：换数据源是少见的运营动作，换源当场批量确认一次，比冒充风险更可控。

## 后果（Consequences）

- 运营者换数据源之后，回访观众会以新观众的身份出现，带着一条指向老观众的合并建议；在待确认页逐个"同意"之前，主播看不到这些观众的长期印象与约定，会把他们当生人招呼。待确认页目前没有批量同意，回访观众多时要一位一位确认。
- 新部署与沿用旧默认的部署行为一致改为不自动关联；有意设了 90 天的运营者也会被钩子改成 0，靠迁移时的警告日志发现并改回。
- 关联判定的代码路径没有删减，只多了"时限大于 0"这一个前提；时限大于 0 时的行为与 ADR-047 完全相同，相关测试改为显式传入时限。
- 配置项说明与数据源指南同步改写：默认不自动关联，需要的人把 `name_match_window_days` 调成大于 0 的天数。
