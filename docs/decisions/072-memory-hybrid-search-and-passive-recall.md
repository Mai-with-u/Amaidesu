## 背景（Context）

账本上线后，她能用的旧事有三个出口：常驻简报、线索推送、回想工具。回想工具每个关键词做一次包含匹配、多个词取交集，不排序：东西查得到，可观众换个说法就查不到，结果多了也没有先后。线索推送只有两种触发——某位观众开口、某个游戏开着——没有"聊到某个话题就想起来"的路径。她的台词一场一两百句，累计已上千句，只靠字面包含会越来越难找准。

调研的证据强度是中低：合成数据上，规则方案对"同义改写"这类说法几乎召回不到，加上向量后总召回从约六成升到约八成，补上的主要是同义改写、半截引用和缩略；BM25 遇到她的长台词会大量误触发；同步算向量每批要多几十到一百多毫秒。调研的总体结论是"向量不是必需的"——这些数字全是合成数据，这个直播间的真实说法分布未知。第一版仍然做全并默认开启，是因为要的是完整、默认开启的系统；代价是靠离线评测集与测试直播演练把关，数字不达标就调阈值或触发规则。

和 [ADR-062](062-persona-and-ops-belong-to-maibot.md) 的关系：那里把开播之外 7×24 的人设与运营记忆划给 MaiBot；这里是开播时她自己记得的事，两边互不读写。这套检索不接 MaiBot 的长期记忆系统，也不依赖它：MaiBot 的问题恰恰出在那套重型记忆（切分吃掉大量 token、同步准备记忆拖慢回复、注入失败只打 debug 日志），这里只做小规模的派生索引，不另起服务、不在说话路径上调模型、失败一律打 warning。

## 决策（Decision）

核心一句：**正本不变，另建一份可随时重算的派生索引；关键词与语义两路各排名次再融合；每批决策前按地点、触发词、意思相近三路补推线索卡，语义一路配置了嵌入服务才开。**

1. **索引什么**：档案行（全部场次，含被挤出快照的行）、承诺（未了结与已了结，判误记的不收）、她播出的台词（只收正式场里没被标成没送达、播出满 30 秒的正文，不收她回应的那条弹幕原文）、游戏事件（白名单只收里程碑与阶段汇报，游戏聊天与玩家肢体动作不收）。**观众弹幕不进持久索引**：设计公理 1 不让观众的话进跨场记忆，弹幕一旦进了跨场索引，删观众、"忘了我"就多一份要追删的副本，跨场检索也等于给她一张观众档案；本场弹幕本来就在她的对话窗里。
2. **索引是派生物**（存储 v29）：每类来源一张向量表、一张 FTS5 全文表，行号就是来源行主键。向量表外键级联；全文表靠触发器跟着来源行删除，来源正文被改（删观众替换昵称、台词标成没送达、清空承诺原话）时连同向量一起删掉等重算；全文表打开 FTS5 自己的 `secure-delete`，删掉的词元不留在影子表里。场次改成彩排时，在改类型的同一个事务里删掉那一场的台词与事件索引，查询时还按场次类型再过滤一遍。中文按"两个字一组、相互重叠"切开后建全文索引；拼音层用 pypinyin（MIT，已核许可证原文）。
3. **嵌入**：`model.toml` 的 `[embedding]` 段引用 `llm_providers` 里的一个条目，走 OpenAI 兼容的 `/embeddings` 接口（基础设施装配通道，不是工具）。默认指向硅基流动的 BAAI/bge-m3，密钥留空即视为没配置：语义一路关掉、退回关键词与规则，启动时打一条点名服务商的"未配置密钥"警告，WebUI 模型页写明"语义检索没开"。嵌入全程异步：后台索引任务按水位补算，失败按退避重试、记 warning 带原因，不挡全文索引、不挡直播。换嵌入模型时整表重算，不混用新旧向量。
4. **外发什么**：配置了嵌入服务后，会发给服务商的有观众弹幕正文（不带昵称、代号、外部 ID；发过"忘了我"的观众的弹幕不发）、游戏情境（游戏名、存档名、地点名、委派原话；发出去前把已知的名字——身边看到的玩家、本场发过弹幕的观众、游戏公屏里说过话的人——换成"玩家"，先遮名再截短），以及补算索引时的档案行、承诺、她播出的台词、游戏里程碑与阶段汇报。和发给对话模型服务商属于同一类外发；想让数据不出本机，`base_url` 填本地端点。
5. **查询与融合**：关键词一路在全文表里按 BM25 取前 50，语义一路按余弦取前 50，按名次融合（每路贡献 1/(60+名次)，不比较两路原始分数）。过滤：存档按 [ADR-069](069-game-memory-per-save.md) 判定、只取正式场、有待执行删除请求的观众相关行先过滤。
6. **回想工具**改用这套检索：默认相关度高的在前，出处、时间词、遮名规则不变；能查到游戏里程碑与阶段汇报；语义一路用不了时在结果末尾注明"这次只按字面查"。
7. **被动想起**：每批 Planner 之前同步算候选，每批至多 3 张卡，优先级为 对象开口 > 走到地点 > 触发词 > 游戏开着 > 意思相近。
   - **走到地点**：角色从 48 格外走进某个记住的地点 24 格内（同一存档，每个地点每场至多一次；位置读到超过 3 分钟就不判），推挂在那个地点的档案行。地点来自游戏 Agent 发的地点动静事件（`game.place.noted`），只落库，不进她的对话时间线、不促发决策。
   - **触发词**：观众弹幕里出现档案行的触发词，或老梗栏里的梗及其别名；归一化后匹配，三个字以上的词再按拼音匹配。她自己最近几句台词里说到触发词也算（自触发），但同一条每场只推一次，老梗不算，防她越说越多。
   - **意思相近**：只拿最新几条、归一化后够长的弹幕逐条去查，余弦不低于 0.65 且融合后排进前 3 才推；弹幕一到就在后台算查询向量，组装这一批时没算好就不推，决策不等它。游戏情境（存档、走到跟前的地点、手上的委派）变了才查一次。不认"她刚说过"，对某位观众的承诺不走这一路。
   - **不推**：本场已经点名用过的（承诺 `约#N`、档案行 `档#N` 同一套判定）、常驻简报里已经列着的、别的存档里的、发过"忘了我"的观众触发的、模拟消息与遗忘命令本身。
8. **档案行带编号**：常驻简报与线索卡里的档案行带 `档#N`，Planner 可以在 `use_memory` 里点名；点名后台词只拿到那一行的标题。点名过的行留在简报里，标"（本场已提过）"，提醒她别再主动提；线索卡对它用上即停。
9. **看得见**：每推一张卡记一行 `memory_cue_log`（哪一路命中、分数、用上的时刻，只记条目编号，不记观众身份），复盘页列出本场线索卡；索引任务每轮补了多少记日志。开关 `memory_passive_recall_enabled` 与 `memory_passive_recall_vector_enabled` 默认开。

## 替代方案（Alternatives）

### 只做关键词，不做语义

**暂不采纳**。调研结论确实是向量不是必需的；但只靠字面，观众换个说法就想不起来，这正是要补的。语义一路做成"配置了才开"，不配就是只做关键词。

### BM25 也用于被动推送

**拒绝**。BM25 遇到她的长台词会大量误触发；推送路径只用触发词、地点与带阈值的语义相似，BM25 只给回想工具排序。

### 观众弹幕进持久索引，方便跨场想起

**拒绝**。理由见决策第 1 条：跨场记忆不收观众的话，删除与遗忘也少一份副本。

### 接 MaiBot 的长期记忆

**拒绝**。理由见背景：边界上是两份不同的记忆，工程上那套系统的问题正是这里要避开的。

### 加一层重排序模型

**暂不做**。重排序会降低"该说没有就说没有"的比例；只在离线评测里量，召回提升且拒答不降才开。

## 后果（Consequences）

- 直接改变她说什么的是被动想起：观众提到触发词、换个说法提旧事、角色走到某个记住的地点，她都可能想起相关的旧事。风险是把"意思相近、其实不是一回事"的两件事说混，自触发让她越说越多；靠阈值、每场次数上限与用上即停挡，复盘页的线索卡面板看得到每张卡为什么推。
- 语义阈值 0.65 是先定的，离线检索评测集还没做；等真实场次数据与评测集出来，按"无关文本逐条误推不超过千分之二"校准。
- 嵌入服务慢或断，回想与被动推送都退回字面匹配，漏得更多，但不挡说话。
- 承诺没有触发词（要改找承诺提示词，推迟），规则一路只认档案行与老梗；承诺只能经语义一路被想起。
- 本场记住的地点清单只取本场的地点动静事件，不取速览缓存里的完整地点表。
