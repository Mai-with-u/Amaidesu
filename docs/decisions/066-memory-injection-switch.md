# ADR-066：记忆注入切到账本（常驻简报 + 线索推送 + memory_recall / 旧三份记忆停写并退出提示词）

- 状态：已采纳；接续 [ADR-065](065-memory-ledger-shadow-run.md) 的影子运行阶段，把注入侧从旧的场次回顾、长期记忆 MEMORY.md、观众画像与本场备忘录切到承诺账本与场次档案；旧表与旧文件原样保留，存储面清理由 [ADR-067](067-irreversible-memory-cleanup.md) 接棒
- 日期：2026-11-04
- 实现提交：与本篇同笔交付，`git log -- docs/decisions/066-memory-injection-switch.md` 可检索

## 背景（Context）

ADR-065 先把新的记忆账本（承诺与场次档案）写了起来，但只写不读：Planner 仍然靠三份自由文本——每场一份回顾、一份长期笔记、每位常客一段印象——外加模型自己写的本场备忘录。影子运行的意义是攒真实数据再切；切的时候要回答两个问题：注入什么、怎么保证不出错。

旧注入有三个问题：整段塞进提示词的文本随场次变长（长期笔记加回顾最多约 3k token，且每场都在长）；答应观众的事没有行级状态，说完没做完、说放弃没改、记错改不掉；模型不知道某条旧事该不该提、该对谁说，只能凭自由文本猜。

## 决策（Decision）

核心一句：**跨场次记忆只从账本读，三个出口：开播时拼一次的常驻简报、每批算一次的线索推送、模型按需查的回想工具；旧的回顾 / 长期记忆 / 画像 / 备忘录停写、也不再进任何提示词。**

1. **常驻简报**（系统提示词末尾，开播拼一次、整场不变）：最近一个已整理场次的档案行（标题加她的原话），加不针对具体观众、不挂游戏的未了结承诺（最老在前至多五条，更多的折成一行指回回想工具）。拼好整场不重算，前缀缓存才命中。
2. **线索推送**（参考段，每批 Planner 调用前算）：①本批发言人名下有未了结承诺 → 对 ta 的承诺卡，只给动作标题（原话可能夹着 ta 的私事，不给 Planner 看）；②当前开着的游戏有挂它的未了结承诺 → 游戏卡，给标题与原话；③老观众在场一行（本场之前来过至少三场、她本场还没回应过、没有待删请求）；④本批遗忘命令的回执行。每批至多三张卡，同一张卡每场至多两次且间隔十分钟，本场台词的记忆引用里已出现的编号不再推（用上即停）。
3. **回想工具 `memory_recall`**：替代 `memory_recall_session` / `memory_recall_viewer` / `streamer_notebook` 三个旧工具。查她已播出的台词、档案行、不针对具体观众的承诺与本场观众弹幕；不按观众名字查人（关键词是昵称时忽略并提示），跨场结果里的已知昵称换成"某位观众"。
4. **两档写法**：同一套渲染函数产出 Planner 档（带编号与原话）与说话档（只有动作标题、不带编号）；Planner 点名用 `reply` 的 `use_memory`，编号必须在常驻简报或本批卡片里，否则忽略；点名的那条渲染成说话档交给表达侧，编号随 `streamer.speech` 落进台词的记忆引用列。
5. **人设加老梗栏 `inside_jokes`**：运营者手写的直播间老梗只进 Planner 系统提示词，观众提起时才接；不进 Replyer 与快嘴，免得说话模型自己反复玩梗。
6. **旧路径停写**：旧的收播整理（回顾、长期记忆合并、画像更新）与备忘录工具不再运行；与 MaiBot 的共享笔记同步停用。表与文件原样保留，旧 WebUI 端点下线（画像与长期记忆页）。

## 替代方案（Alternatives）

### 继续用旧的整段文本，只把提示词写得更细

**拒绝**。问题不在措辞：自由文本没有行级状态，了结不了、删不掉、也没法核对原话；而且文本随场次增长，越到后面越挤占决策上下文。

### 账本与旧记忆长期并行注入

**拒绝**。同一件事会在常驻简报、回顾与长期笔记里各出现一次，模型对同一件旧事念叨三遍；切一半留一半还让"用上即停"失真——它只认账本的编号。

### 保留旧工具，仅新增 `memory_recall`

**拒绝**。三个旧工具各查一张表，模型要先猜该用哪个；而且旧回顾与画像本身就是自由文本，查回来仍是旧的形态。旧工具的前提（回顾/画像表）已经不写，留着只会查到空。

## 后果（Consequence）

- 提示词的记忆占用从"随场次增长"变成"有上限"：简报最坏约 1.5k token（常见约 260），线索段常见约 300；回想工具一次至多八条。
- 记忆不再是"文本里的模糊印象"，而是带状态、带原话、可纠错的条目：说完了看得到、判误记不会重新登记、删观众时对 ta 的承诺一并删除。
- 需要一个可观测面：WebUI 记忆页只留账本三块（承诺 / 下播整理 / 场次档案），旧画像页与长期记忆编辑页下线。
- 代价：运营者在切换前要把旧笔记里还想兑现的条目手建进账本；旧回顾里的历史细节不再注入，想知道只能靠回想工具翻档案。
- 旧表（`session_recaps` / `viewer_profiles` / `live_sessions.notebook_text`）与 `memory/MEMORY.md` 成了死数据，保留到阶段 4 清理；这期间它们不再被写，也不会再出现在提示词里。
