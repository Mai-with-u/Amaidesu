# ADR-069：游戏里的记忆按存档分开（游戏 Agent 报眼下的存档 / 整理时按台词时刻记下存档 / 别的存档里的事不催、不当成眼前的事）

- 状态：已采纳；细化 [ADR-066](066-memory-injection-switch.md) 第 1、2 条里"挂游戏"的口径——游戏卡由"正在玩这个游戏"细化为"正在玩、且是这个存档里答应的"，常驻简报的上一场档案按眼下存档分块；三个读出口与两档写法不变
- 日期：2026-11-05
- 实现提交：与本 ADR 同批交付，按 subject 检索：`git log --grep "记下所属存档"`、`--grep "游戏工具面可报当前存档"`、`--grep "认出所在存档"`、`--grep "生物名册按世界编号"`、`--grep "下播整理给档案和承诺记下存档"`、`--grep "简报和线索卡按眼下存档分开"`、`--grep "主播按游戏眼下存档读记忆"`、`--grep "记忆页标出承诺与档案在哪个存档"`；也可 `git log -- docs/decisions/069-game-memory-per-save.md`

## 背景（Context）

同一款游戏可以有很多个互不相干的世界：Minecraft 的不同存档、不同服务器。"屋顶封好了""下次把北边的桥修完"只在说它的那个世界里成立。实测换了新存档开播，主播第一句就是"今晚先把那间漏风屋子的屋顶封上"——那间屋子在另一个存档里，眼前的世界里什么都没有。

原因是记忆只认游戏、不认存档。已删除的 ADR-058（长期笔记条目化）第 8 条按"对象与游戏"分发：决策层只放开着的游戏的条目，快嘴只拿全场条目。ADR-066 把记忆切到账本后沿用了"按游戏"这一层：挂游戏的承诺只在她正在玩那个游戏时进游戏卡，上一场的档案行整段进常驻简报（档案行连游戏都没记，游戏名只写在标题里）。快嘴（说话模型）从 ADR-066 起已经不读任何记忆，ADR-058 那半条随之失效，本篇不涉及它。另外几处与世界有关的状态也不分存档：MC Agent 的待办、工作笔记与近期上报整个进程共用一份；主播"手头的事"（委派工作台）连跨场都不清，下一场开头她会看到"两小时前在游戏里开始做某事"。

要分存档，先得知道眼下在哪个存档。MaiCraft 在 `events` 每页与 `observe(self)` 里报 `world{id, name, source}`，不在世界里为 null，换世界会当场叫醒挂着的长轮询（接口见 MaiCraft 仓库的对外接口文档）。旧版 Mod 不报这个键。

## 决策（Decision）

核心一句：**游戏 Agent 认出眼下的存档并经工具面报给主播；和世界有关的记忆写入时记下存档；主播读记忆时代码分清"本存档的""别的存档的""不确定的"，别的存档里的事不催她提起、也不当成眼前的事给她。**

1. **存档身份只认编号**：存档 = 游戏给的不透明编号（只做相等比较）+ 给人看的名字（只显示，可能重名、会改名）。框架类型 `GameSave`；不分存档的游戏（或版本太旧、报不出存档）根本不给。
2. **MC Agent 认存档**：三态——旧版 Mod（回复里没有 `world` 键，与以前完全一样不分存档）、不明（`world` 为 null 或还没读到）、认出。唯一喂入点是目标跟踪每读一页，读 `observe(self)` 时顺手也喂。"换存档"只认"上一个认出的编号被另一个取代"：回主菜单再进同一个存档不算，不看事件流编号（重进同一个世界它也会变）；进程启动后第一次认出只记下。
3. **MC 的工作文档与名册按存档分**：待办、工作笔记、近期上报按存档分桶，换存档收起旧的、换上新的（新存档是空的），回老存档还原；切换只经状态对象的一处入口，读写入口不变。换存档时手上有任务，就告诉它任务是在旧存档里接的、先看眼前再决定继续还是上报；同时发一条换存档里程碑（进时间线、落游戏事件）。生物名册改按世界编号分，第一次按新编号读之前把旧版本存在旧编号名下的名册整份搬过来（新编号名下已有就不搬、不混）——名册里有主播起的名字和谁死了，游戏里重看不出来。
4. **拉取，不推送**：主播每个决策窗开窗前从 `ToolRegistry.current_saves()` 拉一次各游戏眼下的存档（游戏工具面的只读方法）。推送事件在开场第一轮（症状发生的时刻）往往还没有，而组合根不许"启动时补读全局状态"；当前存档只随人在游戏里的操作慢慢变、读它不触发任何行为、不形成"输出→决策→输出"的环，属于数据流的发现平面，那里的措辞由"静态"放宽为"静态或慢变"。
5. **写入时记下存档，由代码认**：游戏事件由发布方填存档（MC Agent 与身体事件采集器各按自己读到的页）。下播整理时，挂了游戏的档案行与新承诺按那句台词说出口的时刻对上这一场各游戏的存档段（同一游戏连续在同一存档的事件并成一段，A → B → 回 A 是三段），取台词时刻之前最近开始的那一段；比所有段都早的取最早一段；这个游戏这一场一条带存档的事件都没有就不记。存档不让模型猜；档案提示词只多一个可选的 `game` 字段（与承诺同一口径），评测另有档案挂游戏的样本集。
6. **读时四分**（判定集中在 `src/agents/streamer/memory/saves.py`）：

   | 游戏眼下 | 记忆记着存档 | 记忆没记存档 |
   |---|---|---|
   | 报不出存档 | 照旧 | 照旧 |
   | 还没进存档 | 别的存档 | 不确定 |
   | 在存档 b 里 | 是 b：本存档；否则别的存档 | 不确定 |

   - 线索推送：游戏卡只推本存档的；别的存档的不推（推送是催她提起）；不确定的照推，卡面让她先对一对眼前的世界。对某位观众的卡照推，注明是在哪个存档里答应的。
   - 常驻简报：开头写眼下在哪个存档（还没进存档就提醒别把游戏进度当成眼前的事）；上一场在别的存档里的事每个存档折成一行，只说做过几件、细节去回想里查；没记存档的游戏行注明不确定；上一场玩时还没记存档的游戏在块尾注一句。存档没换、表没变时输出逐字节不变，前缀缓存照旧命中。
   - 回想工具：挂游戏的档案行与承诺逐条注明在哪个存档、是不是眼下这个；她过去说过的话，那场只在别的存档里玩过时注明。
7. **手头的事**：开播清场（已聊话题与本窗回执只属于一场，全部清空）；直播中某个游戏从一个认出的存档换到另一个，清掉这个游戏的委派与补充要求。两种情况都先问任务账本：账面还在做（受理、在跑、停着等定夺）的委派连同它的补充要求留下——开播前调试时派的、上一场没走下播留下的、换存档时游戏 Agent 还没决定接着做还是上报的，身体手上确实还有这件事，清掉了她再派新的会被拒；已结算、查不到或没装账本的清掉。换存档这件事由游戏自己的里程碑进时间线，主播这边不再写一遍。
8. **旧数据不丢不藏**：升级前的游戏事件、承诺、档案行存档列为空串，按"不确定"照给并注明；记忆页的游戏标签写成"游戏「存档名」"，运营者看得出是哪个存档里的事。

## 替代方案（Alternatives）

### 别的存档里的记忆一律隐藏

**拒绝**。承诺与上一场的事是真实发生过的，观众问"上次那房子呢"，她该答得出"那是在旧存档里"。真正的错误是把它当成眼前世界的事；代码已经把"在哪个存档"写进文本结构（折成一行、逐条注明），不必藏。

### 不改档案提示词，按"上一场玩过哪个存档"整块标注

**拒绝**。一场里换过存档、或聊天与游戏交替时，整块标注分不出哪几行是游戏世界里的事、是哪个存档的；只有让每行带上游戏，代码才能按台词时刻认存档。代价是提示词改动要进发版门槛的 live 评测，评测器为此加了档案挂游戏的样本集。

### 让模型在整理时填存档

**拒绝**。存档是可以确定判断的事实（事件与台词都有时刻），让模型填只会多一种出错的方式；模型只判断"这件事是不是游戏里的、是哪个游戏"。

### 游戏 Agent 换存档时推送事件，主播订阅

**拒绝**。开场第一轮往往还没有任何游戏事件，订阅晚了拿不到当前值；拉取一次是一个内存读，代价可以忽略。

### MC 换存档时直接清空工作文档，不还原

**拒绝**。来回换存档是正常玩法，回到老存档时笔记里"北边的桥还差三格"仍然成立；按存档收起再还原，成本只是内存里多几份文档（进程重启照旧清空）。

## 后果（Consequences）

- 新开存档时，主播不会再把旧存档里的建筑和进度当成眼前的事，也不会被游戏卡催着去做另一个世界里的事；回到老存档，相关记忆原样回来。
- 存储升到 v26：`commitments`、`archive_lines`、`game_events` 加存档两列（`archive_lines` 另加 `game`），迁移只加列；名册的旧行在第一次按世界编号读时搬过去。
- 一场里一条带存档的游戏事件都没记下（短场次、旧版游戏）时，挂游戏的条目认不出存档，按"不确定"处理；里程碑类事件越多，认得越准。
- 主播每个决策窗多一次内存读（各游戏工具面的眼下存档）；存档变化时常驻简报变一次，前缀缓存失效一次。
- 档案提示词多一个字段，评测器 `scripts/memory_eval/archive_game.py` 量游戏归属准确率；目前只有 dry 自检，没有对真实模型跑过 live，是否列进发版门槛另行决定。
- 别的游戏想分存档，只需在自己的工具面实现 `current_save()` 并在游戏事件里填存档，读侧不用改。
