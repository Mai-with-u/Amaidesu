# ADR-050：场次分正式与彩排（真假按场分流 / 记忆两条线 / 模拟观众只进彩排场）

- 状态：已采纳；取代 ADR-006"数据治理"一条的落地方式（按行 `simulated` 过滤）与 ADR-045"回放场次不对外同步"的判断依据（改按场次类型）
- 日期：2026-10-29
- 实现提交：五笔，可用 `git log --grep` 按 subject 检索——`feat(session): 场次加正式与彩排类型`、`fix(streamer): 修复回顾因不分场次类型串入调试场`、`feat(simulator): 模拟观众只进彩排场`、`fix(maibot_sync): 修复重启后补写的回放回顾仍推给 MaiBot`、`feat(dashboard): 开播分正式与彩排 + 场次类型可更正`

## 背景（Context）

场次被四类下游使用：明细分组、主播记忆（场次回顾 / 观众画像）、对外同步（MaiBot）、统计复盘。后三类真正要问的只有一句"这场的观众是不是真人"，而场次表此前只记来源（`source`：谁开的场），答不了这个问题。

ADR-006 定下"模拟数据在数据面是二等"，落地方式是每条明细带 `simulated` 标记、消费方按行过滤。实际情况是：

- 没有一处统计查询真的按 `simulated` 过滤；
- 主播记忆完全不看它：回放场、调试场收播照样写回顾，下一场正式开播把最近一场当"上一场"注入，昨晚的调试被当成今晚直播的前情；
- 按行过滤本身不够：主播对假观众说的话是真的主播发言（`simulated=0`），回顾的原料一大半是主播自己说过的话，行级标记拦不住；
- 模拟器生成模式不开场次，没有场次时消息不落库、模拟观众读不到上下文，用的时候只能手动开一场，这场在库里和真直播一模一样；
- 对外同步靠进程内记下"哪些是回放场次"，进程重启后补写的回放回顾照样推给 MaiBot（ADR-045 的"回放场次不对外同步"在这条路径上失效）。

## 决策（Decision）

**真假按场分流：每场开启时声明类型——正式（`live`，面向真实观众）或彩排（`rehearsal`，模拟、回放、调试）；类型与来源正交，进行中不改。**

1. **存储**：`live_sessions.kind` 列（存储 v19）。存量回填只认明确证据：回放来源，或"有观众明细却没有一条来自真实平台的真实观众、且没收到过平台观看数推送"判彩排；没有观众明细的场次判不出真假，保持正式。判错的场次在 WebUI 手动更正（只允许改已结束的场次）。
2. **主播记忆两条线**：回顾照常每场都写，读取按类型过滤——正式场只接正式场的回顾，彩排场只接彩排场的；`memory_recall_session` 往前数也只数同类型场次。未开播时按正式场读。观众画像只更新真假与场次类型相符的观众：正式场只更新真实观众，彩排场只更新模拟观众。
3. **模拟观众只进彩排场**：模拟器生成模式没有场次时自开一场彩排；正式场进行中拒绝启动；正式场开播时自动停下，且只收口自己开的场次。不支持正式场里混入模拟观众（见替代方案）。
4. **对外同步只认正式场**：开播、收播、回顾三类事件都带场次类型，上报器按类型跳过彩排场；整场记录按场次行的类型过滤。
5. **开场入口必须声明**：场次管理器 `open_session` 的 `kind` 没有默认值；WebUI 开播弹窗默认跟随弹幕接入（接了 B 站弹幕算正式，没接算彩排），手动选过以手动为准，且不记进"上次开播意图"。

行级 `simulated` 标记保留，用途收窄为"这一条消息是不是造出来的"：整场记录推送按行跳过模拟消息、回放可只放模拟消息、观众身份按真假分行。

## 替代方案（Alternatives）

### 继续按行过滤，把各消费方补齐

**拒绝**。拦不住"主播对假观众说的真话"，回顾仍会被污染；而且每个新消费方都要记得加条件，漏一处就串。场次是记忆与同步的天然单位，在场上判一次比在每行上判更可靠。

### 允许正式场里混入模拟观众（冷场时补人气）

**拒绝**。一是与架构的核心判据相悖：空房间冷启动要求没人时主播靠自己也能推进，用假观众补人气等于绕开这个目标；二是对真实观众不诚实，他们会听到主播回应不存在的弹幕；三是事后分不干净，主播一次处理一批消息，回复只关联其中一条，回顾必然被污染。

### 由系统自动判定类型（例如看有没有接 B 站弹幕）

**不采用为唯一依据**。开发者也可能接真实房间做测试，一场真直播也可能整场没人发弹幕。自动推断只用作开播弹窗的默认值，类型由开场的人声明。

### 彩排场的回顾不写

**拒绝**。彩排里同样需要测"主播记不记得上一场"，彩排线有自己的回顾才测得了。

## 后果（Consequences）

- 调试、回放、模拟的场次不再被当成正式直播的上一场，也不再推给 MaiBot；彩排里可以照常测跨场记忆。
- 开场多了一个必选项；忘了选的代价由弹窗默认值兜住，选错了下播后可改。
- 存量里"一场没人发弹幕的真直播"会保持正式；"只用控制台调过的场次"会被判彩排。若有真直播只靠控制台输入，需要手动改回正式。
- 统计复盘尚未按场次类型过滤：WebUI 的观众列表与互动分析仍包含模拟观众（模拟观众是独立的观众行，可按观众行的模拟标记区分）。
