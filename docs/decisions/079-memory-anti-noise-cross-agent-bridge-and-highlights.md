# ADR-079：记忆检索抗干扰降噪、双侧记忆桥接与档案名场面分层（扩展 ADR-071 / ADR-072 / ADR-077 / ADR-078）

## 背景（Context）

随着跨场直播场次积累到数十场、单存档与全库台词滚大至数万轮规模，[ADR-071](071-rolling-session-archive.md)、[ADR-072](072-memory-hybrid-search-and-passive-recall.md)、[ADR-077](077-memory-zones-opening-wrapup-ttl-and-in-stream-correction.md) 与 [ADR-078](078-game-social-facts-boundaries-and-governance.md) 建立的四表记忆体系在离线跨场基准（含带约 48 场干扰对话的标准检索集与万轮混库）及真实联机直播里暴露出三组结构性短板：

1. **长期积累后的检索竞争、同源占坑与弱命中误塞**：
   - 下播整理的档案行与公开承诺均引用主播原话台词作为证据，混合检索时裸台词与引用它的账本行常同时上榜，把前 8 个坑位挤成 4 条有效信息；
   - 观众或模型传入带疑问词、时间口语词的查询时，FTS5 `"或"` 查询捞出大量只撞上虚词的旧话，而 RRF 只看名次不看绝对相关度，遇到库里根本没有答案的问题也会 100% 塞满 8 条似是而非的旧记录，诱导主播张冠李戴；
   - 同一件事在多场直播里被反复随口念叨、或状态在后一场更新（如"之前没封顶 → 昨晚封顶了"）时，缺乏同分档近场偏置与近似复读限额，旧状态容易压过新状态，或连续七八条复读旧话霸满全部名额；
   - 主播直播说话常把前因后果拆成紧挨着的两句短话，单句索引与单句展示会漏掉半截语义或断章取义；此外超长文本或纯空白脏行进入嵌入队列会触发远端 400 或校验报错并拖入整队退避。
2. **主播侧与游戏 Agent 侧的存档记忆孤岛**：
   - 游戏侧持久化的当前存档工作笔记与待办（`game_work_docs`）对主播侧 `memory_recall` 不可见，观众问"基地施工材料还差多少"时主播翻不到游戏侧记下的清单；
   - 反过来，多人联机服里经玩家公屏核实的共享设施惯例与领地边界（`game_social_facts`）只注入给主播决策层，游戏侧自主推进委派目标时完全不知情，容易出现主播嘴上答应守规矩、角色却直接拆改公用设施的割裂。
3. **长线存档的"中程共同经历断层"与纯杂谈场次失忆**：
   - 滚动快照此前只有"永久静态设定（`lasting`，如取名与住处）"和"最近两三场普通进展"两档。播到第 30 场时，第 5 场花好几晚建成的大工程落成、首次击败首领或全直播间爆笑的戏剧性翻车既不算静态取名，又早已滑出近期窗口；
   - 到了纯杂谈回（眼下未进入任何游戏存档），常驻简报把所有挂游戏的记忆折成一行计数，主播想跟观众聊起以前一起玩游戏的高光往事时眼前一片空白。

## 决策（Decision）

在不引入在线大模型重排、不放宽观众弹幕防投毒与跨场隐私红线的前提下，分三层补齐检索抗干扰、双侧只读桥接与名场面分层：

1. **回想检索抗干扰、同分档近场偏置与去重折叠（`textmatch.py` / `search.py` / `recall.py` / `embedding.py`）**：
   - **剥离疑问虚词与双路相关性底线**：新增回想专用分词 `fts_recall_query` 剔除中英高频疑问词与口语虚词（整句全为虚词时自动回退防空查）；回想调用语义路设余弦底线 `RECALL_MIN_COSINE = 0.50`，低于底线的向量不参与 RRF 投票；纯字面路径剪除零实词凑数尾行，整次查询仅剩字面弱擦边时最多返回 2 条并附"拿不准就直接说记不清了"提醒。
   - **同分档有界新近度偏置**：单路 BM25 分差在 3% 以内或语义余弦差在 `0.015` 以内的候选归入同一相关度分档，仅在至少 2 条候选的同分档内部按主键新旧施加封顶微幅加分（不跨档反超独占高分档的早期唯一事实），让状态更新自然排在旧状态之前。
   - **单句向量正本不变 + 同场 ±30 秒邻句切词与还原**：`live_chat` 的向量正本与 `text_hash` 保持单句原样（不触发存量重算、不稀释单句余弦）；全文切词拼入同场前 30 秒已播出主播台词并在检索层扣除纯借词回声；回想渲染时按 140 字预算拼合同场前后 30 秒紧邻主播台词（严禁混入观众弹幕与未送达废稿）。
   - **三重去重防霸榜**：① 裸台词与引用它的档案行或公开承诺同时命中时，在更靠前名次上合并为带标题、状态与存档注记的账本行；② 已被更靠前入选条目完整拼入正文的同场邻句不再重复占坑（`RecallEntry.covered_chat_ids` 记录实际承载主键）；③ 剥离虚词与句尾语气词后词项数 `>= 3` 且 `Jaccard >= 0.85` 的跨场/同场近似复读台词，单次最多保留 2 条。
   - **索引毒丸防护**：待补队列统一过滤含制表符/换行在内的纯空白文档；`EmbeddingClient.embed` 送往远端前将超长单段截断至 `6000` 字符，不改调用方文档指纹。
2. **按存档硬隔离的双侧只读记忆桥接（`recall.py` / `minecraft/social_rules.py`）**：
   - **工作文档 → 主播回想**：`MemoryRecallService` 只读接入 `work_docs_repo`，仅检索 `current_saves` 中眼下已认出存档的笔记小节与未完待办（非当前存档绝不串入），统一按跨场口径遮蔽已知观众昵称，与历史检索共享 8 条总上限。
   - **公共社交规矩 → 游戏侧固定层**：`MinecraftAgent` 通过工厂透传只读接入 `social_fact_repo`（与 `src/agents/streamer/` 保持零导入依赖），仅在认出存档与新开委派任务时异步刷新内存缓存（推理步内零查库）；只收 `sharing`、`setting`、`members`、`works` 四类行动边界事实（至多 6 条、单条限 80 字），严格拦截未经人工锁定的观众弹幕作证行与无引文归纳行，换存档立即清退旧规矩缓存与开局消息，续做未变时走增量去重不刷屏。
3. **档案名场面层与按说话模式分区展开（迁移 `v43` / `rolling.py` / `zones.py` / `render.py`）**：
   - **存储与提取硬护栏**：迁移 `v43` 为 `archive_lines` 与 `archive_snapshot_lines` 增加 `highlight INTEGER NOT NULL DEFAULT 0`；下播整理提示词允许对大工程落成、首次首领击杀或代表性高光互动标 `highlight: true`，代码强制**单场新事最多保留前 2 条**、**未经游戏记录核实的完成说法一律强制 `highlight=False`**、人工锁定行禁止模型重标。
   - **快照独立名额**：滚动快照为每个游戏存档 `(game, save_id)` 及不挂游戏的直播间各自独立保留至多 6 条名场面（按最近提起时间取舍），快照总安全上限由 40 调至 48，既不被两三场日常琐事挤出，也不挤占【这个世界里】12 行稳定名额与【最近几场】普通事件名额。
   - **按说话模式双态渲染**：常规边玩边说模式（`speaking_mode="gameplay"`，含游戏委派短暂等待回复期间，保持前缀缓存稳定）严守存档隔离，仅将当前存档已滑出近期窗口的名场面追加在【忘不掉的名场面】（至多 4 行），别的存档照旧折入计数；流程单切入纯杂谈环节（`speaking_mode="zatsudan"`）时自动重渲简报，展开跨存档【一起经历过的名场面】（至多 6 行，行内显式写明所属游戏与存档），并统一纳入合法点名名单与"本场已提过"防复读护栏。

## 替代方案（Alternatives）

### 把前后邻句直接拼进 `IndexDoc.document` 同时算全文和语义向量

**拒绝**。改写 `IndexDoc.document` 会改变所有历史台词的 `text_hash`，导致线上与评测库整表重算向量；更重要的是把三句话揉成一个向量会严重稀释单句核心事实的余弦相似度，且让长篇接话轮在关键词与向量两路同时压过简短原话轮。保持向量单句正本不变、只在全文切词与回想展示阶段拼合邻句并做借词回声折算，兼顾了跨句召回与单句精度。

### 全局按时间戳给新台词加固定线性分，取代同分档有界偏置

**拒绝**。无条件时间加分会让昨天随口聊到的擦边闲聊跨档反超十场前唯一一次说清的具体设定。仅在 BM25 分差 `<= 3%` 或余弦差 `<= 0.015` 的同分档内部做有界偏置，且严守跨档天花板，才能既让状态更新排前、又不伤早期孤本事实。

### 让 `MinecraftAgent` 直接复用主播侧的社交事实渲染器，或放宽未锁定弹幕行进游戏侧

**拒绝**。游戏包导入主播包违反 Agent 间包隔离契约；且直播间观众弹幕未经人工锁定若流入游戏侧，一条"西边木屋无主随便拆"的恶意弹幕就会诱使角色当场拆毁队友建筑。独立放在 `src/agents/minecraft/social_rules.py` 并只放行公屏有据行或 `human_locked=1` 行是必要防线。

### 把代表性名场面直接标成 `lasting=True` 塞进【这个世界里】

**拒绝**。`lasting` 用于名字、住处、长期规矩，混入历史事件会迅速挤满【这个世界里】的 12 行配额把宠物名字与基地坐标挤掉，且无法区分"当前存档常态"与"杂谈回可跨存档回忆的高光往事"。独立 `highlight` 列配合说话模式分流，才能在边玩时守住存档隔离、在杂谈时打开共同回忆。

## 后果（Consequences）

- 回想工具消除了账本同源双占坑位、邻句重复占坑与跨场复读霸屏，无答案或弱相关查询不再塞满 8 条误导旧话，同分近况更新稳定排在旧状态前。
- 主播回想能直接查到眼下存档的工作笔记与待办，游戏角色执行委派时也能主动遵守当前存档经公屏核实的共享设施与领地规矩，两边严守存档边界与防投毒红线。
- 长线存档播过数十场后仍能留住最具代表性的共同经历，纯杂谈环节不再因未进游戏存档而对过往高光场面"失忆"，同时不增加常规游玩时的跨存档串味与唠叨复读风险。
