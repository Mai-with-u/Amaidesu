# ADR-080：思考节拍与发言节拍解耦

状态：已采纳
日期：2026-11-18
实现提交：随"发言节拍解耦"批次并入 dev（定位：`git log --grep="发言节拍"`，或本 ADR 路径的历史）

## 背景

主播"说话期间不思考"的根源不是 TTS 出口的背压闸，而是 rundown_ready 防抖兼任了思考调度：开窗判定对照 `last_speech_ms`（开口后 15 秒内不开窗），而语音播放完全落在这段闲置里——播放期间没有任何决策在跑。出口闸（wait_playback）只在队列有未播话时咬合，防抖节拍下几乎不起作用。场 70 实测：21% 台词出口前等 8 秒以上（最长 29.5 秒），语音占全场 36%。planner 时延为输出主导（输入 86% 缓存命中），压缩输出等于压缩思考本身，决策提速路线不成立。另查明出声前核对器共享表达档配置，继承 `reasoning_effort=high`，30 次调用生成内容的 98% 是思考段。

## 决策

把"想"与"说"拆成两个独立旋钮：

1. **开窗连续**：rundown_ready 开窗判定不再对照 `last_speech_ms` 防抖——上一轮出口即具备开下一窗的资格，思考不间断；
2. **发言侧限速**：防抖保留原值（距上次开口 ≥ `rundown_ready_interval_ms`），但执行点移到发言放行时刻——只管"这句几时能说"，不再管"几时开始想"；
3. **队列上限**：TTS 出口放行条件从"队列排空"改为"未播的话 ≤ max_pending"（新增配置键，默认 1；0 = 旧行为排空）——限住"想到就说"的过时上界，burst 时队满即暂停开窗；
4. **核对器独立化**：独立 profile（无思考小模型，可配置）+ 裁决契约收缩为三选一（放行 / 重复 / 作废：理由）——删除"保留"删句改写分支及其忠实度护栏；作废丢弃后沿用既有踢腿唤醒下一窗；planner 侧作废退回重想一步的既有路径不动。

## 替代方案

- **仅短句**（预算 60→30，已先行实施）：缩短每格等待，但不改变"播放期间无思考"的结构；
- **欠一句为主**：治积压不治"没轮到想"，在防抖兼任调度的结构下不触及根因；
- **完全解耦（不限队列）**：过时无界，核对器拦不住"话题已过时"类软过时；
- **决策提速**（轻窗降配 / 裁输入）：输出即思考、模型已顶格，压缩输出=降质，已否决。

## 后果

- 决策窗频率在说话期约 ×1.8，费用约 3.5 → 4.5–5 元/场（沉默期本已连续开窗，增量只在说话期）；
- 发言频率由防抖旋钮独立控制（`rundown_ready_interval_ms` 现行默认 30s，见 `src/agents/streamer/config.py`；最终取值仍待用户拍板，调大则发言更稀疏）；
- **行动频率风险**：窗频上升连带放大派活/操作决策机会——实施前置 = 行动类工具限流盘点，不足则补节流；
- 核对耗时降至 1 秒级，进入每轮关键路径可接受；
- "保留"分支删除后，半新半旧的候选整句丢弃或退回重想，"该说没说"的量在下场观察；
- 台词"一句话一件事"判据（`.omo/drafts/speech-one-thing-criterion.md`，不入库）作为验收标准配套实施；判据本身随复盘持续修订，不入本 ADR。
