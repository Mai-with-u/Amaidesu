# ADR-078：游戏社交事实的定位、与三类记忆的分工边界及证据隐私治理（对齐 ADR-068 / ADR-074）

- 状态：已采纳；补充立档游戏社交事实子系统（`game_social_facts`），对齐 [ADR-068](068-memory-privacy-retention-and-forget.md) 的话随人删口径与 [ADR-074](074-viewer-defined-memory-needs-approval.md) 的观众弹幕经人批准规则，划清与 [ADR-065](065-memory-ledger-shadow-run.md) / [ADR-071](071-rolling-session-archive.md) / [ADR-075](075-game-players-by-uuid.md) 的职责边界
- 日期：2026-11-13
- 实现提交：`feca53db2b058a5c7d8ee1aa8b754791586c5f1e`（删观众删玩家清理社交事实原话与游戏工作文档）、`d8789b852b8a70104d773bdcbcb0cabfc62ca542`（弹幕改走待审候选、代号整词还原、无据归纳不常驻与陈旧事项降级）；存量表与基础链路见 `git log -- src/modules/storage/repos/social_facts.py src/agents/streamer/memory/settle_social.py` 与 `git log -- docs/decisions/078-game-social-facts-boundaries-and-governance.md`

## 背景（Context）

多人联机游戏（如多人服务器存档）里存在一类既不属于"主播自己做过的单场事件"、也不属于"某一位玩家走到眼前才需要想起的个人往来"的环境常态：这是个几人服还是公开服、哪些玩家彼此是同伴或邻居、哪座机器或仓库大家公用、眼下服务器里谁正在牵头修什么大工程、主播在这个圈子里平时扮演什么分工、还有什么没弄明白的事。

此前上线 `game_social_facts`（存储迁移 `v38`，含场内登记工具 `streamer_social_fact` 与下播整理第四次调用 `settle_social.py`）时没有同步立档 ADR，导致两类严重问题：

1. **与既有三套跨场记忆职责重叠、缺少清晰边界**：`members`（成员关系）与 [ADR-075](075-game-players-by-uuid.md) 的游戏玩家档案、`works`（进行中的事）与 [ADR-065](065-memory-ledger-shadow-run.md) 的承诺账本及当场委派、`her_role`（她的角色）与 [ADR-071](071-rolling-session-archive.md) 的场次档案稳定行各自有一套表、上限与注入段；`works` 没有陈旧降级机制，几场前别人随口提过的一句"在修刷铁机"会永久占据高优先级常驻名额。
2. **违反既有证据审核与隐私删除红线**：
   - 场内工具允许直接拿观众弹幕作证据写入现行 `game_social_facts`，绕过了 [ADR-074](074-viewer-defined-memory-needs-approval.md)"观众的话必须她当场接受且经人批准才进跨场记忆"的防投毒防线；
   - 下播整理允许模型不引任何原话凭空归纳 `her_role` 与 `open_questions`，归纳行不带任何未核实标记就跨场每轮常驻，且一场内跨多个存档发言时会误挂到最后一句公屏所在的存档上；
   - `game_social_facts` 的证据外键设为 `ON DELETE SET NULL`，删观众时完全未触碰该表，删玩家时只把名字换成"一位玩家"却把玩家公屏原话原封不动留在 `quote` 列里，违反了 [ADR-068](068-memory-privacy-retention-and-forget.md) 话随人删的合规要求（同期新增的按存档持久化游戏工作文档 `game_work_docs` 也需纳入玩家脱敏范围）；
   - 下播整理把模型输出的"玩家1、玩家2"还原成真名时按插入顺序逐个调用字符串替换，同场发言玩家达到 10 人及以上时，`"玩家1"` 会吃掉 `"玩家10"` 的前缀造成张冠李戴。

## 决策（Decision）

保留 `game_social_facts` 作为**按"游戏 + 存档"隔离的多人环境共享背景表**，用六条规则锁死它与既有记忆的分工边界、证据门槛、时效降级与隐私删除：

1. **四套跨场记忆的正交分工边界**：
   - **场次档案（`archive_lines` + 快照，ADR-071）**：记**她自己亲历的叙事与设定**（她起的宠物/地点名、她的住处、这一场做成了什么进展、直播间共同梗），证据只能是她自己播出的台词。
   - **承诺账本（`commitments`，ADR-065 / ADR-077）**：记**她当众答应要做、尚未兑现的债与心愿**（对大家、对某位观众或对某位玩家），核心生命周期是"未了结 → 兑现了结 / 搁置 / 作废"。
   - **游戏玩家档案（`game_players` + `game_player_interactions`，ADR-075）**：按 UUID 记**单个玩家与她的一对一履历**（现名与曾用名、打招呼、送礼、切磋、一起做过的一件事），只在该玩家本窗开口或冲她做动作时以"玩家卡"按需推入参考段，平时不常驻。
   - **游戏社交事实（`game_social_facts`，本篇）**：按 `(game, save_id)` 记**当前游戏世界里多人共处的群体环境与公共秩序**（封闭六类：`setting` 环境形态、`members` 玩家间关系、`sharing` 共享惯例、`works` 服务器里他人或大家正在推进的事、`her_role` 她在群体中的常态分工、`open_questions` 待弄清的环境疑问），证据主要来自游戏公屏上在场玩家的原话；只趁她正在玩该游戏且处于对应存档（或未分存档的全局项）时注入参考段【游戏社交事实】，每类每存档至多 4 条现行、每次注入至多 12 条。凡属"她答应别人的待办"一律归承诺账本，凡属"她只和某一个人发生过的往事"一律归玩家互动表，不在社交事实重复记账。
2. **证据门槛：观众弹幕一律走待审候选，无引文模型归纳行不进常驻**：
   - 场内工具 `streamer_social_fact` 只允许**游戏公屏里已核实身份的玩家原话**经逐字引文校验后直接写入现行 `game_social_facts`；若引用的消息是直播间观众弹幕，代码核对她本场确已送达过对该弹幕的回应后，只写入 `viewer_candidates`（`kind="social_fact"`，待人工批准后才转入现行社交事实並锁定），她尚未回应过的弹幕直接打回并说明无需重试，与 [ADR-074](074-viewer-defined-memory-needs-approval.md) 完全对齐。
   - 下播整理第四次调用产出的无逐字引文模型归纳行（`her_role`、`open_questions` 中 `quote` 为空且未经人工锁定的行），以及历史遗留未锁定的弹幕作证行，只落库供 `memory_recall` 检索与后台审核查看，**不进入每轮常驻参考段【游戏社交事实】**，除非运营者在后台编辑确认并置 `human_locked=1`。
   - 一场内玩家公屏横跨两个及以上不同 `save_id` 时，未绑定具体公屏行的归纳条目默认归入整款游戏级（`save_id=""`），不盲目挂到最后一句公屏所在的存档上。
3. **代号整词还原**：
   - 下播整理将模型输出的 `"玩家N"` 还原为玩家真名时，统一采用单趟整词边界正则 `玩家(\d+)(?!\d)` 查表替换，杜绝 10 人及以上多人同场时短编号吞掉长编号前缀。
4. **"进行中的事（`works`）"两场陈旧降级与自动让位**：
   - 未被人工锁定的 `works` 条目若距其创建或最近一次更新（`updated_session_id` / `created_session_id`）已隔过两个及以上时长达标的已完结正式场仍未再被证实，读时自动降为"待确认的旧进展"：在【游戏社交事实】排序中排到所有新鲜条目末尾，渲染时显式标注"（已隔多场未再证实）"。
   - 当某存档下的 `works` 达到 4 条上限、场内工具或下播整理有带新证据的新 `works` 写入而模型未显式指定 `supersedes` 时，代码自动挑最老的一条已降级陈旧 `works` 予以取代（`status='superseded'`），无需人工清理也不会堵死新进展入账。
5. **合规删除：先按证据外键删本人原话行，再跨表脱敏提及名（`privacy.py`）**：
   - 删观众（含观众发"忘了我"到期清理）：在删除 `live_chat` 触发外键置空**之前**，先按 `evidence_chat_id` 硬删除所有拿该观众弹幕作证据的 `game_social_facts` 行；其余由他人作证但正文中提到该观众现名或曾用名的 `game_social_facts`、`memory_corrections` 及 `settle_checkpoints` 行，将名字替换为`"一位观众"`。
   - 删游戏玩家（含玩家在公屏发"忘了我"或随关联观众连带删除）：在删除 `game_players` / `game_chat` 触发外键置空**之前**，先按 `evidence_game_chat_id` 硬删除所有拿该玩家公屏原话作证的 `game_social_facts` 行；其余提及该玩家现名或曾用名的 `game_social_facts`、`game_work_docs`（按存档持久化的游戏笔记正文与待办 JSON 列表）、`memory_corrections` 及 `settle_checkpoints` 一律替换为`"一位玩家"`。

## 替代方案（Alternatives）

### 撤掉 `game_social_facts`，全部并入场次档案或游戏玩家档案

**拒绝**。场次档案只认"主播自己播出的台词"作唯一证据，而多人服里的公共规矩与分工往往是其他玩家在公屏说出来、主播只回了一个"好呀"甚至只听进心里；若放宽场次档案去收别人的话，会动摇档案快照的证据纯洁性。反过来若全部塞进单个玩家的 `game_player_interactions`，只有那个玩家开口时才会推卡，他不在线时主播走进公用仓库就会忘掉"这座仓库大家公用"。独立保留按存档隔离的轻量环境背景表最贴合实际读取时机。

### 允许场内工具把观众弹幕直接写成现行社交事实，事后再靠人工巡检删掉

**拒绝**。与 [ADR-074](074-viewer-defined-memory-needs-approval.md) 已否决的理由相同：直播间观众人数远多于同服白名单玩家，哪怕只有一场被恶意弹幕塞进"某玩家是内鬼""服务器禁止某玩法"，主播就会整场按假规矩行动并复述给全场听；进 `viewer_candidates` 待审能零成本挡住投毒与隐私入库。

### 删观众、删玩家时只把 `game_social_facts.quote` 里的名字抹掉，保留原话行

**拒绝**。`quote` 存的是被删除人自己说出的整句原话，即便抹掉名字，原话里的口吻、私事细节仍留在库中且继续每轮注入提示词，不符合 [ADR-068](068-memory-privacy-retention-and-forget.md)"本人作证的话随人删"的承诺；只有先按证据外键整行删除本人作证行、再对他人行做名字脱敏，才与承诺账本和玩家互动表的删除强度一致。

## 后果（Consequences）

- 四套跨场记忆各有唯一职责与出场时机：她的亲历归档案、她的欠债归承诺、单人履历归玩家卡、多人服公共背景归社交事实，提示词与维护者不再混淆该往哪张表写。
- 观众弹幕无法再绕过人工审核直写跨场社交事实；无引文的模型归纳行退出每轮常驻注入，消除了"模型猜错一句角色定位就跨场洗脑"的风险。
- 多人服超过两场没人再提的旧工程自动降级垫底并在满额时给新工程让位，不再永久霸占 4 条配额。
- 删观众与删玩家路径补齐了 `game_social_facts`、`game_work_docs`、`memory_corrections` 与 `settle_checkpoints` 的外键前置清理与名字脱敏，由 `tests/modules/storage/test_privacy_players.py` 回归测试守护。
