# ADR-074：观众定下的事经人批准进记忆（修改设计公理 1：观众的话只有经人批准、且她当场接受过，才进跨场记忆 / 她说欠着、账上找不到的事同样只列候选）

## 背景（Context）

设计公理 1 是"承诺与档案只从她播出的原话长出来，观众的话进不了任何跨场记忆"。可直播里常有观众起的名字、定的设定、造的梗，她当场接受了（"可以呀，就按你说的叫"），却没有自己把那个名字复述一遍。整理只认她的原话，于是找不到可引的那半句，下一场就忘了；观众问"上次我们定的名字呢"，她一脸茫然。

全自动收观众的话不行：观众能借此往她的记忆里塞东西（"你上次说过你怕水"），也会把自己的个人信息塞进来。MaiBot 那边群多、审不过来，只能自动写；直播只有一个直播间，一场就几条，人审得过来。

还有一类不是观众的话、但同样不能自动登记：她说"上次答应过你们……""这个还欠大家的"，可承诺账上（未了结与已了结）找不到对得上的一条。可能是账漏登记，也可能是她顺着观众的话编的，代码分不出来。

## 决策（Decision）

核心一句：**观众定下、她当场接受了的事，和她说欠着、账上找不到的事，整理时列成待审候选；人批准了才进记忆，批准前对她完全不可见。**

1. **公理 1 改成**："观众的话只有经人批准、且她当场接受过，才进跨场记忆"。她自己说的照旧自动生效；她自己复述过的（台词里说出了那个名字或设定）照旧写成普通档案行，不列候选。
2. **观众定下的事**：写档案那次调用顺带列出 `viewer_candidates`，不加调用次数。代码逐条核对：
   - 只认她回复一条真实观众弹幕（不是模拟观众）的那几行；弹幕那一段与她那句的一段都要逐字；
   - 模型另写观众定下的名字或梗词，它必须在标题里、也在那条弹幕原文里原样出现：观众只问了"叫啥"、名字是她自己起的，弹幕里就没有这个词，不列，写进整理报告的未登记清单（档案提示词 1.9）；
   - 标题或两段原话里出现手机号或长串数字、年龄、住址、学校、联系方式这类模式的，整条丢掉，只计数，内容不进整理报告；
   - 和本场新写、上一份档案里的行（同一句作证据或归一化后标题相同）、驳回过的候选（同一条弹幕或同样标题）去重，一行只列一条，一场至多 5 条；标题里模型写的"观众N"代号换成"观众"。
3. **她说欠着的事**：找承诺那次调用顺带列出 `claimed_missing`，同样不加调用次数；整理时把已了结的承诺标题一并交给它比对。代码核对：引文是本场她播出的一行台词的逐字片段；和账上（未了结、已了结、本场新登记）任一条标题相同、和本场作为新承诺或了结证据的那一行是同一行、或驳回过的，都不列；一行至多一条，一场至多 3 条；有个人信息模式的丢掉。她又当众重新说定的（"上次答应的，下次一定做"）按承诺口径直接登记，不列候选。
4. **存储**（v31）：`viewer_candidates` 一条候选一行，类型分"观众定下的"与"她说欠着的"，挂在观众那条弹幕（她说欠着的一类在她是回应某条弹幕时才有）与她那句回应两条台词记录上，外键级联；`archive_lines` 加来源（主播 / 观众）与观众那条弹幕两列。待审的列出后 14 天没人审自动删掉，只按时间、不按场数。
5. **批准后**：
   - 观众定下的：写成一行观众来源的档案行，原话是她那句回应的逐字片段（与"原话只取自她播出的台词"一致），挂着那条弹幕；锁住并放进最新快照最前面（同 ADR-073 的人新增行）。常驻简报、线索卡、回想结果在这一行后面注明"和观众一起定的，不记得是哪一位，别点名"，说话档只给标题，防她编出一个具体的人；她那句回应常常点了那位观众的名，原话照存，常驻简报、线索卡、说话档渲染时按那条弹幕的发送者用过的名字换成"那位观众"；
   - 她说欠着的：登记成一条未了结承诺，证据是她说欠着的那一句，之后照常被提醒、被了结；
   - 驳回的留着，同一条以后不再列。
6. **审核入口**：记忆页的观众候选区逐条显示观众那条弹幕（已知昵称遮成"某位观众"）、她那句回应和标题，标题可以先改再批；她说欠着的一类旁边列出账上字面最接近的几条承诺，便于看出是漏登记还是编的。批准前确认框说明：这条记忆挂在那位观众的弹幕上，ta 被删除或发"忘了我"时一起删掉。
7. **批准前不可见**：简报、线索卡、回想、检索索引都只读档案行与承诺，不读候选表；契约测试守护主播侧除整理外不得引用候选表。

## 替代方案（Alternatives）

### 观众定下的事自动进记忆

**拒绝**。投毒与个人信息都挡不住；直播一场就几条，人审得过来。

### 守住原公理，让她自己复述

**拒绝**。靠提示词让她每次都复述一遍观众起的名字，既不自然，也管不住；漏一次就忘一次。

### 她说欠着的直接登记成承诺

**拒绝**。顺着观众说"对对我上次答应过"的，登记了就真成了一笔要兑现的账，之后每场被提醒。

### 单独一次调用列候选

**未采纳**。并进写档案、找承诺两次调用不加调用次数；档案调用的台词本来就附着被回应的弹幕原文。

## 后果（Consequences）

- 她会开始提观众定下的设定（"你们上次给它起的名字"）；不会再出现观众问起定过的名字她却茫然。她嘴上说欠着、账上没有的事，不会因为没人审就自己变成一笔账。
- 观众发"忘了我"后，ta 定下的设定随 ta 的弹幕一起删掉：设定来自 ta 的话，按 [ADR-068](068-memory-privacy-retention-and-forget.md) 的口径应当一起删。保留期清理只清工作数据，批准进记忆的那条弹幕不删，否则档案行会被级联删掉。
- 风险：她当场的回应可能是敷衍或误解，人批的时候要看她那句是不是真的接受了；批了投毒的候选就进了记忆。评测里的红队组（塞假设定、塞个人信息、冒充运营）只统计被列出的比例，给审核的人参考。
- 库里不存是哪位观众定的，她最多说"大家定的"。
