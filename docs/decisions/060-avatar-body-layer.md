# ADR-060：面捕合成器加一层身体动作（部分取代 ADR-057 的 Warudo 动作片段：站姿跟着持续的情绪自动换 / 说话时偶尔叠一个身体动作 / 手势由事件与主播点名触发 / 各平台各自翻译、做不到的跳过）

- 状态：已采纳；部分取代 [ADR-057](057-avatar-platform-drivers.md) 中"Warudo 内置的头部动作与站姿作为动作片段登记、由 `avatar_act` 触发"的安排，其余不变
- 日期：2026-11-01
- 实现提交：可用 `git log --grep "身体" -- src/modules/avatar scripts` 检索

## 背景（Context）

面捕合成器（ADR-052、ADR-054）每帧给出的是面部捕捉的通行规范：表情系数、头部转角与位置、视线，外加躯干的前后左右。这套东西只够让真人面捕的"上半身一个头"动起来；手臂、整体的身体语言，面捕本身就不采集，真人主播靠的是动作捕捉或手动触发的动作。被动参数做不出"开心时双手放在身前、想事情时托腮、来礼物时挥手"。

ADR-057 移植 Warudo 时，蓝图里带了几段内置动作作为动作片段：点头一次、点头两次、摇头、歪头、低头看向一边，以及放松、思考、默认三个站姿，由主播经 `avatar_act` 点名触发。真机核对后发现两个问题：

- 头部动作和面捕合成器重复了：有意的点头、摇头、歪头早已由面捕合成器写在头部转角里，蓝图里再播一段头部动画，两边会抢头；
- 站姿交给主播点名，主播几乎不会去点，形象整场一个姿势；而站姿是全身动作，比表情显眼得多，本来就该跟着情绪自动走。

Warudo 自带一套与模型无关的人形动画库（AGIA：待机姿势、叠加动作、一次性动作各几十段），任何人形模型都能直接播放。VTS 上画师做的动作文件可以绑成热键；VRChat 的 SDK 默认模板带一个动作菜单（挥手、指向、欢呼……）。缺的是"什么时候做哪个"的调度。

## 决策（Decision）

- **一小套平台无关的动作词表**，分三类：
  - **站姿**：换上后一直保持，直到换下一个（双手放在身前、单手叉腰、挠后脑勺、思考……共 21 个）；
  - **叠加动作**：叠在站姿上，做完自己消失（左右摇一下身体、仰头笑）；
  - **手势**：一次性动作（挥手、双手挥、指一下、举拳庆祝）。

  业界没有像 ARKit 那样通行的身体动作词表，所以名字由本项目定，平台各自翻译，做不到的跳过。

- **调度放在面捕合成器里**（`BodyDirector`），只订阅它已有的状态，主播包不为身体多发任何东西：
  - **站姿跟着持续的情绪走**。主表情保持 2.5 秒才换站姿，换上后至少停 8 秒，情绪回到平静 6 秒后才回普通站姿；情绪 → 站姿的对照可在 `[tracking].body_stances` 里改。
  - **默认对照不挡脸**：站姿一停就是好几秒，脸是表情的主要载体，默认只选手停在下巴以下的站姿（兴奋双拳握在身前、伤心手按胸口、惊讶双手伸向前……）；哭（捂眼）和思考（托腮）本身就是这个动作，保留。举拳、抱头、捂脸这类站姿留在词表里，按需在配置里对。
  - **Planner 想了 3 秒还没开口就摆思考站姿**。一开口立刻放下，换成这句话情绪对应的站姿（没有就回普通站姿）。
  - **叠加动作只在说话的短语开头出现**。短语开头按口型信号判断：嘴从静默张到一定程度、且前面静默超过 300 毫秒。左右摇身体至少隔 8 秒，开心、兴奋时的仰头笑至少隔 12 秒，任意两个叠加动作至少隔 4 秒。全部按规则确定，不掷骰子。
  - **手势由事件触发**：礼物挥手，SC、上舰双手挥，游戏里程碑举拳庆祝。同一个手势至少隔 10 秒；主播经 `avatar_act` 点名的（"挥手""指一下"……）不受这个限制。

- **运行时把调度器给出的动作提示转给能做的驱动**。驱动实现 `BodyDriver` 协议：`body_supports` 答"这个动作我做不做得了"，`perform_body` 去做。不实现协议的驱动不受影响；主播看到的手势目录只列至少一个平台做得了的。面捕合成器停下时，各平台回到普通站姿。

- **各平台的翻译**：
  - **Warudo**：生成的"Amaidesu 身体动作"蓝图按 `body_<类别>_<名字>` 接收。站姿播待机动画（带 1 秒过渡），叠加动作和手势播一次性动画（叠加动作以叠加方式混合）。AGIA 的挥手是循环片段，一个来回不到 0.6 秒，播一次只闪一下；所以挥手、双手挥在蓝图里换成循环的待机动画，驱动记着当前站姿，挥 2.5 秒后再发一次站姿切回来。默认对照到 AGIA 动画，可在 `[platform.warudo.body_animations]` 换成别的动画。
  - **VRChat**：只做手势，按 `body_emotes` 对到动作表里的动作（默认挥手、双手挥都对 Wave，指一下对 Point，举拳庆祝对 Cheer）。站姿和叠加动作 VRChat 没有对应，跳过；对到动作表里没有的动作时记警告并跳过，不让启动失败。
  - **VTS**：按 `body_hotkeys` 登记的热键触发，站姿绑"换待机动画"的热键，其余绑"播动画"的热键。默认不登记，因为 Live2D 模型的动作文件因模型而异。

- **退役 Warudo 蓝图里的内置头部动作和站姿片段**。头部动作已由面捕合成器负责，站姿改为自动。抛鱼和配置登记的蓝图动作仍作为动作片段保留。

## 替代方案（Alternatives）

- **站姿继续让主播点名**：主播的注意力应该留给说什么、怎么演，每句都考虑摆什么姿势既费 token 又会忘；真人主播的身体语言也大多是下意识的。主播只保留点名手势的能力，用来演"冲观众挥手"这类有意的动作。
- **接姿态估计、生成逐帧身体数据**（比如由语音或文本生成全身动作的模型）：动作更连贯，但要引入重型模型和 GPU 推理，各平台要另接身体追踪协议（VMC 等），且生成的动作好不好看难以控制。成套的现成动画先把"有身体语言"做到，往后需要时再评估。
- **站姿跟着每句话的情绪立刻换**：站姿是全身动作，一句一换会让形象手舞足蹈；所以比表情多一层持续时间判定，并有最短停留时间。
- **叠加动作按随机节奏出现**：随机节奏在调试和测试里不可复现，且容易连着出两个。短语开头 + 最短间隔已经足够不规律。
- **每个平台各自订阅事件、自己决定身体动作**：同一个情绪在几个平台上会各演各的，时间规则也要写几遍；调度留在面捕合成器里，平台只做翻译，和脸部的分工一致。

## 后果（Consequences）

- 同时开几个平台时，身体动作由同一个调度器决定：Warudo 换站姿的同时，VTS 上登记了热键的模型也换；VRChat 只跟着做手势。
- Warudo 用户要删掉以前生成的"Amaidesu 头部动作与站姿"蓝图，重新生成并导入"Amaidesu 身体动作"；`avatar_act` 目录里不再有 Warudo 的点头、站姿片段（点头、摇头、歪头仍在，由面捕合成器做）。
- 默认的情绪 → 站姿、动作 → AGIA 动画对照已在 Warudo 自带模型（Shipilka）上逐个播放核对过；这个模型袖子很大，手抬到胸口以上就盖住脸，挡脸的问题由此暴露。不同模型的身材比例可能需要换动画，在配置里改即可，不用改代码。
- 调校页多了一组身体参数（持续多久换站姿、停多久、叠加动作和手势的间隔、总开关），对所有平台生效；情绪 → 站姿的对照因为是一张表，只在配置文件里改。
- 词表是本项目自定的，往后接新平台时如果出现无法翻译的常用动作，再扩充词表；扩充只加名字，平台没登记的照常跳过。
