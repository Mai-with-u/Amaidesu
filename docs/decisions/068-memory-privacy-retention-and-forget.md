# ADR-068：观众数据可自行删除与保留期（忘了我命令 / 宽限删除 / 不记录名单 / 保留期默认不删）

- 状态：已采纳
- 日期：2026-11-04
- 实现提交：`58d5edeaece2e4ea9768af9218d7666be849ec7b`（feat(storage): 加台词送达列、来访计数与丢弃事件）、`0653a3f64fa2a8c56b8e654f3e0999613fb3c925`（feat(storage): 加遗忘命令、宽限删除、遮名与保留期清理）、`01a32c8c7999750a8fbbc5f1ce8b9ed79ed8c3fb`（feat(dashboard): 观众页加删除、不记录名单与撤回待删）；审查修复：`effde09ed75d1b46fd20c0e9ef785ab3b9ef6044`（refactor(storage): 旧记忆目录移入备份并纳入保留期）、`df9ea42394f9c9b605891c3055c1f8031d35ef1b`（fix(storage): 修复删除观众后整理报告仍留昵称）、`aa23b0106f9a90eb77498078fba023c039dd17d6`（fix(storage): 修复合并观众时丢失待删请求）、`2efc56e990e2ce36af3ee4e565a21d3cf9bdd2bf`（fix(streamer): 修复下播清理抢在道别句落库前执行）

## 背景（Context）

记忆重设计把跨场记忆从自由文本换成承诺账本与场次档案，但这只管"记什么"，没管"记多久、能不能不记"。原状下的空白有三类：

- **观众没有自行删除的入口。** 开放平台协议要求观众能"自行操作完成"删除，实际却只能由运营者在 WebUI 里找到这位观众手动删除；弹幕、付费记录、话题摘要、备份、诊断日志与 WebUI 落盘日志都没有保留期机制，默认永久保留。
- **删除不彻底。** SQLite 默认删掉的行仍留在数据库文件里，预写日志里也有残留；迁移前的整库备份不在任何清理范围内。
- **删除是"一句话就执行、不可撤回的"。** 一句玩笑式的"忘了我吧"会当场删掉老观众的来访计数与对 ta 的承诺，之后也不再认 ta；观众想反悔只能找运营者。

用户给出的两条原则决定了取舍：**策略交给使用者**（保留期只提供机制、默认不自动删除，不替使用者定死），以及**偶发事件不造成不可逆失忆**（删除要有撤回出口）。

## 决策（Decision）

核心一句：**观众发"忘了我"即停止记录、下播后删除（最迟 24 小时，执行前本人可撤回）；删除靠库外密钥的不记录名单认人；所有可清理数据的保留期只提供配置、默认不自动删，迁移前整库备份纳入同一保留期。**

1. **"忘了我"命令**：四类观众消息（弹幕、礼物、醒目留言、上舰）在判场次之前先判命令。非模拟弹幕命中短句表 `[privacy].forget_phrases` 时：这位观众立即可停记——不建新观众、不再落库 ta 的弹幕与身份列，付费只留金额类型时刻；同时写入不记录名单与一条删除请求，等待下播后的清理执行。开播前后的命令同样处理；回放消息不判。
2. **宽限删除**：删除在"发令之后第一次下播后的清理"里执行（这次清理排在道别句落库与下播整理结束之后，本场遮名也留到那时才清空），最迟发令后 24 小时（写入删除请求时排一个 24 小时延时兜底，进程不在运行时由下次启动的清理补上）。执行前 ta 本人发撤回短语 `[privacy].retract_phrases` 即取消；撤回前那几条弹幕不落库，她已叫过 ta 名字的台词已经遮名，撤回不恢复这些。WebUI 观众页显示"待删除（预计执行时刻）"，运营者也可以替观众撤回或解除名单。
3. **不记录名单与库外密钥**：名单存的是外部 ID 的 HMAC-SHA256 摘要（种类 + 外部 ID，不含应用编号），密钥在库外文件（`[privacy].key_path`，默认 `secrets/forget.key`，加入版本控制忽略）。存储启动时：密钥不存在且名单为空就生成；密钥不存在而名单非空就启动报错，给出"找回密钥文件"或"确认放弃名单后清空"两条出路——密钥丢了就无法把名单里的人与外部 ID 对上。
4. **保留期只提供机制、默认不删**：`storage.toml` 新增 `[retention]`，`raw_days` 同时管观众弹幕（含明文外部 ID）、付费三表的身份与留言列、话题摘要、LLM 请求记录的响应正文、迁移前整库备份与迁移时移入备份目录的旧记忆目录；`viewer_absence_days` 管长期不来的观众行（调删除函数，不进不记录名单）。两键默认 0 = 永不自动删除，升级不改任何现有默认值。诊断日志维持现状默认 0（不清理），WebUI 落盘日志不接保留期。
5. **迁移前备份纳入保留期**（用户 2026-11-04 拍板）：升级前自动生成、名字带 `-pre-v` 的整库备份不再是"永不清理"的例外，与其它备份一样按 `raw_days` 清理；默认 0 时行为不变（永不删），设了天数才生效。这一条是审查修复轮补的（原实现把迁移前备份从保留期清理里豁免了），实现见上面列出的审查修复提交。
6. **删除要真删**：数据库连接开 `PRAGMA secure_delete=ON`，每批删除后执行 `wal_checkpoint(TRUNCATE)`；删除某位观众时，她台词、下播整理报告、游戏生物名册与游戏事件正文里 ta 的昵称替换成通用称呼；数据库备份里的残留按配置的保留期消失，日志里的残留见下一条。
7. **已知残留边界写进运维文档与直播公告**：宽限期内的数据仍在库里；诊断日志、WebUI 落盘日志、LLM 请求记录、迁移前备份里的残留按保留期处理（默认长期保留）；复盘数据包导出后不受保留期与删除管辖；单字昵称、ta 没有出现过的场次里她提到 ta 名字、本场内存时间线、运营者手写老梗栏里的昵称不替换；换开放平台应用后 open_id 变化，名单认不出 ta。

## 替代方案（Alternatives）

### 命中即删、不可撤回

**拒绝**。一句玩笑式"忘了我吧"就永久删掉老观众的数据，且只能找运营者解除名单，删掉的数据回不来。宽限删除多一列与一条规则，换掉的是这种不可逆误伤。

### 把诊断日志也设成 14 天滚动删除

**拒绝**（用户明确要求）。日志对复盘分析有用，删不删、留多久交给使用者配置；方案不替使用者定策略。

### 不记录名单存明文外部 ID

**拒绝**。名单本身就是"不许再记的人"的清单，明文存等于换一个地方继续保留可关联身份；HMAC 摘要让不知道密钥的人无法反推外部 ID。

### 只删主库、不清理备份与日志

**拒绝**。删除请求名义上执行了、实际仍能从备份与日志里翻出来；保留期机制就是为这些副本准备的，默认不删只是把决定权交给使用者，不是不提供机制。

## 后果（Consequence）

- 观众获得一条可自行执行的删除路径，删除前还有一次撤回机会；运营者在观众页能看到待删除与名单，可代办撤回或解除。
- 保留期全部默认为 0，默认行为与升级前一致（不自动删）；设了天数后，弹幕、付费身份列、话题摘要、请求正文、迁移前备份与长期不来的观众行一起按该保留期到期。
- 保护名单依赖库外密钥：密钥文件必须与数据库一起单独备份，否则恢复数据库后启动会因"名单非空但密钥缺失"报错。
- 删除有 24 小时上限的宽限期，宽限期是否仍算"及时删除"、以及观众导出与未成年人识别等事项交合规侧复核。
- 清理逻辑在启动时（迁移之后）与每次下播整理后运行；两个保留期都为 0 且没有到期删除请求时直接跳过，不调模型。
