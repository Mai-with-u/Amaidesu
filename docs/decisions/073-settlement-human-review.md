# ADR-073：整理结果的人工审核（整理照旧自动生效 / 人改过的行只有人能动 / 放回的行排在快照最前 / 每次改动留记录 / 整理单独一个模型档位）

## 背景（Context）

下播整理全自动：模型挑哪几件事写进档案、标题怎么写、哪些是稳定的事，写完就进下一场的常驻简报。运营者原先只能删单行、判误记，不能改：标题写偏了只能删掉，整理漏了的事加不回来，被挤出快照的行放不回去。即使删了改了，下一场整理照样可能把人改正过的行去掉、把放回去的行再挤出去，人白改。

另外有两条约束：

- 不能等人审完才生效。用户哪场没审，她那场就失忆，这比记得不准更糟；
- 原话层不能动。档案行的原话与证据台词是"她说过"的唯一凭据，删观众、按句删台词都按它走（[ADR-067](067-irreversible-memory-cleanup.md)、[ADR-068](068-memory-privacy-retention-and-forget.md)）。人能改的只有标题与标记，不能改原话；需要换原话就删了重新从台词里点选。

## 决策（Decision）

核心一句：**整理照旧自动生效，人在事后改；人改过的行之后的整理动不了，人放回、新增的行排在快照最前；每次改动留一条记录。**

1. **存储**（v30，与 v29 分开升）：`live_sessions.reviewed_at_ms`（标已审的时刻，空即待审）；`archive_lines.human_locked`（标题、稳定标记被人改过，或这一行是人新增的）；`archive_snapshot_lines.pinned`（人放回快照或人新增的行，接进新快照时跟着带过去）；新表 `memory_edits` 记每次操作：场次、对象、动作（改标题、标稳定、放回、新增、删除、标已审）、改前、改后、时刻。
2. **人能做的操作**（WebUI 记忆页的档案面板）：
   - 改标题：改档案行的标题，锁住这一行；
   - 标或取消稳定：改最新一份快照里这一行的稳定标记，锁住；
   - 放回快照：把被挤出或被去掉的行插回最新一份快照，标成放回；
   - 新增一行：从这一场她播出的台词里点选一句，再框选其中一段当原话（页面与后端各核一遍是不是那句的逐字片段），写标题；新建档案行，锁住并放进最新快照；
   - 删行：沿用原有的删单行（外键级联撤出所有快照，派生索引一起删）；
   - 标已审：只是状态，整理状态面板显示每场待审与否。
3. **整理怎么认**：
   - 人改过的行，模型的去掉、替换、按重复去掉一律不采纳，整理报告写"人改过的行只有人能动"；稳定与否按人标的算；
   - 放回或新增的行在取舍时排第 0 档，一行不挤，也不占稳定的事那 8 行的名额；加起来超过 12 行时快照跟着超，记忆页提示人去减，代码不替人挤掉；
   - 多场序列评测的字节比对跳过人改过的标题。
4. **改动记录的寿命**：与档案同寿命。场次被删时级联删除；档案行被删时记录还在、改前改后的文本由触发器清空；删观众与"忘了我"把提到 ta 昵称的记录文本整段清空。记录同时是评测的标准答案：人改了什么，就是整理哪里没写对。
5. **整理单独一个模型档位 `settle`**：整理的三次调用与台词预算都改用它，想给整理换更强的模型时不必连直播里的话题总结一起换。存量 `model.toml` 由升级钩子照抄摘要档位那一段（模型、超时、温度都一样），行为不变；已经写过 `settle` 段的不动。换更强的模型要先过发版门槛里的整理评测，过了再由运营者改配置。

## 替代方案（Alternatives）

### 人审完才生效

**拒绝**。理由见背景：漏审一场她就失忆。现在漏审只是"可能记得不准"，WebUI 用待审计数提醒。

### 允许人改原话

**拒绝**。原话是"她说过"的凭据，也是删除路径的锚点；改了原话，档案行就可能写出她没说过的话。要换原话，删掉重新从台词里点选。

### 放回的行受 12 行上限约束，超了自动挤

**拒绝**。人刚放回的行马上被代码挤掉，等于没放；超了就提示人自己减。

### 改动记录永久保留

**拒绝**。记录里有档案标题与原话，删除与遗忘要能管到它；跟档案同寿命，档案行删了文本就清。

## 后果（Consequences）

- 运营者放回、新增的行进下一场常驻简报，她会记得整理漏掉的事；人删掉、改正的误记不会再回来。
- 风险：放回的行太多会把她本场的新进展挤出简报（放回的行排在最前）；改标题改出了原话里没有的意思，她会照着标题说。前者界面提示，后者靠运营者自己把关。
- 整理报告的快照改动清单里会出现"人改过的行只有人能动"的拒绝记录，运营者看得到模型想动哪一行。
- 方案里的"人工改动统计脚本"（读改动记录统计标题被改、行被放回或删掉的比例）还没做，改动记录目前只供 WebUI 与人工翻看。
