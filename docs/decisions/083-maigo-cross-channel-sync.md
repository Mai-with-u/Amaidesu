# ADR-083：通过 MaiGO 打通跨端日内经历与显式确权熟人关联

- 状态：已采纳；部分取代 [ADR-075](075-game-players-by-uuid.md) 第 5 条中“玩家与观众对号永远不告诉她、没有可以告诉她的开关”一节，同时保持该 ADR 关于不自动按昵称对号、游戏行为隔离与遗忘擦除的其余约束
- 日期：2026-11-24
- 实现提交：与本 ADR 同批交付，按路径检索：`git log -- docs/decisions/083-maigo-cross-channel-sync.md`

## 背景（Context）

主播不仅会在直播间互动，还会以同一人格出现在群聊（MaiBot）与外部社媒等长期在线分支中。仅在各端维护独立记忆会产生两类体验割裂：

1. **日内生活与言行断裂**：白天在外部社媒看视频发表看法、或在群里答应观众的事，开播时主播毫不知情；下播后群聊中的她又难以及时承接刚才直播的成果与约定兑现状态，导致不同渠道下的表现像是两个互相割裂的角色。
2. **一刀切阻断跨端认人过重**：[ADR-075](075-game-players-by-uuid.md) 曾以防当众开盒为由禁止任何跨平台身份对号告诉主播。在实际协作与粉丝互动中，问题本质在于“禁止未授权跨账号联想”与“行为规范上不在公开场合点破未公开关联或泄露私聊”，而不应阻止对运营显式确权绑定（或用户自助口令绑定）的熟人建立连续记忆。

同时，`Amaidesu` 本身是按开播/下播生命周期运行的现场决策宿主，本地 SQLite 四表账本（场次、聊天、档案、承诺/玩家）与主决策循环不应被远端中心服务强耦合或拖拽改表结构。

## 决策（Decision）

1. **定位独立薄同步桥**：在 `src/modules/maigo_sync/` 引入可选基础设施 `MaiGOBridge`（配置段 `infra.toml [maigo_sync]`，插在 `[clipping]` 与 `[maibot_sync]` 之间），保持“关闭开关或中心服务离线时 `Amaidesu` 照常单机运行”的零妥协原则，不改本地 SQLite 表结构。
2. **两段式场次交换生命周期**：
   - **开播签出（`checkout`）**：正式场 `live.started` 时一次性向中心交换服务拉取当日冻结慢层生活简报、跨端公开约定、鲜活话头卡、当前游戏存档跨宿主摘要及显式绑定熟人映射（彩排场完全跳过）；简报扩展段整场冻结不带相对跳变时间词，保持规划器系统提示词前缀缓存逐字节命中。
   - **播中轻量消费与心跳**：鲜活话头以负数编号内存虚拟卡片形式注入 `TopicDeck`，选用后随 `heartbeat` 上报已消费状态；熟人映射缓存在内存字典供 `MemoryCueProvider` 在说话路径零网络 I/O 查询，命中且未触发遗忘指令时补充脱敏线索卡。
   - **下播整理后签入（`checkin`）**：待 `SessionSettler` 完成下播账本整理与概览生成后，只推送本场精炼档案行、公开承诺变更、未遗忘玩家互动与已消费话头，不推送原始弹幕流；若中心服务暂时不可达，退避重试后写入库旁待补推文件并在下次启动自动补送。
3. **跨端认人隐私边界（部分取代 ADR-075 第 5 条）**：仅消费经 MaiGO 显式绑定且已完成脱敏的 `prompt_hint`；严格剥离原始数字账号 ID 与 `private` 级私聊内容；本地弹幕「忘了我」及游戏玩家宽限删除标记均立即短路拦截跨端熟人线索生成。

## 替代方案（Alternatives）

1. **直接把 MaiGO 表并入 Amaidesu 数据库或重写本地四表账本**
   - **拒绝**：破坏跨渠道公共设施与直播单机宿主的边界，违背零侵入架构目标，也会拖累直播离线可用性。
2. **保持对跨端绑定熟人绝对保密、仅靠主播每次重启现场猜测**
   - **拒绝**：无法回应已知熟人在群聊、社媒与游戏之间延续互动的真实需求；改为通过显式确权绑定与出口脱敏+可见性隔离精准防泄密。
3. **开播后每轮决策实时请求远端接口**
   - **拒绝**：会把网络抖动与延时带进高频决策与表达循环；签出快照驻留内存可确保播中零网络阻塞。

## 后果（Consequences）

- **收益**：`Amaidesu` 主循环与既有四表记忆完全不受外部服务影响；开播即衔接日内外部见闻与群聊约定，杂谈冷场可通过虚拟话题卡承接，熟人跨平台到访可自然认出而不暴露底层账号或私密聊天。
- **代价与注意**：`[maigo_sync]` 作为纯新增段置于 `[maibot_sync]` 之前以保持存量迁移种子锚点不变；下播尚未整理完前进程强制退出可能导致当场 `checkin` 未送达，待补推队列仅在整理完成后落盘失败时兜底重试。
