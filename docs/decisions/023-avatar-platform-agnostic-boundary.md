# ADR-023：皮套平台无关边界——平台差异全关进适配器

- 状态：已采纳（2026-09-20）
- 日期：2026-09-20
- 实现提交：`3d802fe7b6d55bdadb84c866a510f45170af6e54`（feat: 自动情绪路径与主播域去平台化）

## 背景（Context）

皮套（avatar）三后端 VTS / Warudo / VRChat 均以工具 Provider 形态存在，LLM 直接面对各后端前缀的工具。此前的耦合不在"工具名带平台前缀"——前缀是既有约定（`streamer_reply` 同款），多形象时可区分让主播自选——而在**主播 Agent 代码里写死了平台知识**：

- `speech_dispatcher` 持有一份 `_EMOTION_TO_VTS_PARAMS` 情绪→VTS 参数映射，与 `VTSProvider._emotion_map` 构成双份事实源，且已漂移（词表 12 值只覆盖 10）；
- 情绪扇出由主播域直接构造 `vts_set_expression` 的设备级调用（参数名 + 混合权重），换皮套后端即失效；
- 口型、说话状态等"被动渲染"能力没有归属，主播域也不该知道。

这与游戏无关边界（ADR-018）是同一类病：**翻译知识无家可归，只能塞进调用方**。

## 决策（Decision）

**主播 Agent 包对皮套平台零感知；情绪渲染的翻译与执行全归适配器。** 验收判据与 ADR-018 同构：`grep src/agents/streamer/` 必须零 `vts|warudo|vrchat`。

- **自动情绪路径 = 适配器订阅事件**：适配器订阅 `streamer.speech`（发言事实携带情绪 17 值 + 强度，与 TTS 启用正交），把每次发言反射为一次 `set_expression` 调用——每个身体各自对发言事实作反应，多形象天然成立且不是广播路由。选择事件订阅而非主播直调的理由：Agent 彻底不碰皮套、适配器需要整条发言事实才能决定怎么演、情绪是潜意识产物被动产生。
- **说话状态走事件**：适配器订阅 `tts.utterance.started/finished` 维护"是否在说话"（VTS idle 说话时暂停摇摆、Warudo 说话点头），不再从口型件兼任（旧 `is_speaking` 恒 False 的断线由此接通）。无 TTS 引擎时该事件无发布者、说话反应不触发——**刻意接受的不对称**（无音频即无声可同步），情绪路径不受影响。
- **绑定逻辑函数级共享**：`src/modules/avatar/speech_binding.py` 提供订阅绑定纯函数，三后端各自在 `setup`/`cleanup` 生命周期挂载退订；不引入基类。
- **编排层只发事实**：`SpeechDispatcher` 删除情绪扇出（`_schedule_vts_emotion` 与映射表），只发布 `streamer.speech` 业务事件，不再知道"谁在消费情绪"。
- **口型是共享分析件 + 平台渲染器**（详见口型帧级通道 ADR），主播域同样零参与。

## 替代方案（Alternatives）

- **域级工具名 `avatar_*` Facade**：被否决——装配路由在装配期已完成，Facade 是多余一跳（ADR-007 对 TTS Facade 的同款否决）；多形象时反而损失前缀区分度。
- **主播直调皮套工具（情绪扇出留在 dispatcher）**：正是被拆除的现状。主播域为此持有设备参数表，换后端即改主播代码，且扇出策略（TTS 启用门）与皮套无关。
- **统一中间表示 / 专用事件链 / 输出管道**（旧 Intent 模式复刻）：明确禁止——旧 Intent 因虚构中间表示、应答机化、翻译知识无家可归被整体废弃，三禁是本次设计的硬护栏。

## 后果（Consequences）

- 主播包通过平台名验收（grep 零命中）；换/加皮套后端不改主播代码，加内容 = 加包 + 配置。
- 适配器需要消费发言与 TTS 生命周期事件，事件总线的传递时序成为渲染时延的一部分（装饰性路径，可接受）。
- 自动情绪路径无 `tool.result` 遥测（不经 ToolRegistry），失败经适配器日志兜底；队列满丢最旧时表情会为未播的话出现——已知的可接受小瑕疵。
- 共享绑定函数住 `avatar` 包内，跟随皮套域演进。
