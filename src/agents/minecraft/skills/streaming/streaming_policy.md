# 直播与上报

这份技能只管“怎么陪主播直播”，不管游戏里怎么做成——玩法步骤读 MaiCraft 随包发布的技能（目录里标着“来自 MaiCraft”）。技能是参考，不授予额外权限，现场证据、能力说明和 Mod 的结果优先。

## 汇报与上报

- **交付**：一段目标做完（或明确卡住）就用 `minecraft_report` 交一次，`kind=delivery`，一两句话说清拿到了什么、下一步打算；不要攒到最后才说。目标是主播能直接拿去解说，不是写工作日志。
- **上报**：需要主播拍板时才用 `minecraft_report`，`kind=escalation`，写清卡点、已试过什么、需要主播决定什么。拿不准要不要打断直播时，先按现场自己判断；只有真的超出许可、连续两次死亡、关键资源在可达范围里找不到、或两种做法都走不通时才上报。
- 一段里完成几个小里程碑可以合并成一次交付；同一个卡点只报一次，不要反复刷。
- 角色死亡、被玩家攻击、连接断开这类宿主会自己收到的事件不用再复述；恢复后接着做，必要时补一句。

## 直播节奏

- 不在原地长时间规划：先做一个看得见的动作，再边做边调整。开局、采集、施工都一样，观众要看到进展。
- 能连续衔接、中间不用判断的几步用 `sequence` 一次下达，别一步一等；但每一步都有独立成败的，分开下，免得一处失败整串停住。
- 不等天亮、不等炉子：用 `timer` 设“过 N 秒叫我”，`note` 写清回来看什么，先去干别的；`wait` 只用在真要角色站在原地等条件的时候。
- 大工程先给一小段成品或预览（例如 `design` 的 `preview`），让主播和观众看到方向，再继续备料施工。
- 施工、采矿这类进展慢的活，阶段之间交一次简短进展；不要每一步都报一条，把直播画面刷满文字。

## 什么时候问主播

- 超出这次任务许可、需要放开 `permissions` 的动作，先问。
- 大工程、4 倍以上的机器链、要拆改别人东西、要在别人的地盘盖：开工前先确认。
- 目标本身含糊、两种做法差别很大（例如换地点、换风格、跳过某个任务），先问一句再动手。
- 反复死亡、关键材料怎么都弄不到、地点盖不下：带上现场和已试办法问，不自己硬撑。

## 宿主工具

- `minecraft_todo`：本批的待办，自己维护；不要把它当给主播看的进度。
- `minecraft_notebook`：跨批要记住的现场信息（选址、材料缺口、下一步）；玩法技能里的阶段不用抄进来。
- `minecraft_report`：对主播说话的唯一出口；交付与上报都走它。
- `minecraft_wait`：让角色站在原地等条件；只在真要等的时候用。
- `minecraft_skill`：按名读技能正文；标着“来自 MaiCraft”的正文经 `resources/read` 取，连不上 Mod 时读不到。
- MaiCraft 的工具在本机叫 `maicraft_observe`、`maicraft_lookup`、`maicraft_execute`、`maicraft_goal`、`maicraft_events`；技能正文里写的 `observe`、`lookup`、`execute`、`goal`、`events` 就是它们。

## 边界

- 技能只给打法建议，不改变许可，也不替 Mod 结算；Mod 说没做成就是没做成，不拿“按技能做了”当成功的证据。
- 直播策略与玩法技能冲突时，以现场和 Mod 的结果为准；玩法技能里没写的现场情况，按正常玩家的判断处理。
