# 建造：画图、预览、施工、改建

盖东西分两件事：`design` 画图纸（不动角色，当场返回），`build` 把图纸盖到世界里（后台推进）。先画、先投影给观众看，再动手；直播里“看它一步步盖起来”本身就是内容。改一栋已有的房子也是这两件事，只是图纸从现场读出来，见“改已有的房子”。

## 定方案

- 先把要求收成几句：盖什么、给谁用、多大、几层、什么风格、门朝哪、盖在哪。主播没说的按“像样、能住、别太大”自己定，不为细节停下来问。
- 第一次盖某类建筑从小的来（例如 7×5 的木屋），盖成了再加附楼、加层。大建筑材料成百上千，施工要很久，观众会等。
- 先定体量再做细部：一个主体量加明显小一些的次体量 → 屋顶轮廓 → 门窗节奏 → 材料分工（基座、墙、框架、屋顶、窗，三四种主材）→ 少量点缀。只换木头颜色不算新设计。

## 选址

- `observe(what=scene, grid=true)` 看地形平不平，平地最省事。网格只画俯视一层，看一栋已有的房子（门洞、地面多高、屋里哪里空）不用它，用 `design(operation=read_site)`。图纸不检查地形：盖在坡上、坑里，施工会挖掉挡路的天然方块、垫上缺的，但室内没写的格子不会被清空，地形会留在屋里。坡地上要么换平地，要么在图纸里把室内写成空气。
- 离玩家的房子远一点：碰到玩家的东西施工会停下来问。
- 选好就用 `remember` 记个地名，锚点、后续加建、回来都按它。

## 画图

- 先 `lookup(id=maicraft:design)` 读能力说明，图纸格式和例子按说明里指的资料读，不凭印象写字段。
- `design(operation=create, drawing=…)`：用对象（盒子、板、楔形、圆柱、屋顶……）描述，一单位一格；墙用空心加壁厚，不逐格堆方块；重复的窗间、柱廊做成组件；对象起用途名（`MainFloor`、`RoofLeft`）。门洞、窗洞用开孔。
- 返回里看三样：`materials`（每种材料几件，就是备料清单）、`bounds`（多大）、`overlaps`（哪里叠了）。校验错误一次报全，按定位改那几处再提交，不整张重画。
- 明明写的是数组，却被报“objects 要是数组”“cells 必须是 JSON 数组”（`received` 里是 `{"item": …}`，数字成了字符串）：这是工具调用把嵌套数组弄坏了，不是写法错。把整个 `drawing`（逐格施工就是整份 `cells`）写成一段 JSON 字符串再交，入口会照原样读，`notes` 里说明按对象或数组处理。
- 改图用 `operation=update` 按名字改（只改位置会保留材质和尺寸），每次存成新的一版 `design_id`。看细节用 `operation=inspect`。
- 校验通过只说明图纸能展开，不说明好看、能住：自己核一遍门通到外面、楼梯有净空、屋顶没压到室内。

## 预览

- `design(operation=preview, design_id, target=锚点, rotation?)` 把图纸投到世界里，观众在画面里看到半透明的房子（白色是要放的方块、红色是要清空的、蓝色是要倒桶的，水或岩浆）。不占用身体，可以边预览边做别的。
- 主播或观众对样子、朝向、位置有意见：改图或换锚点、换 `rotation` 再预览，满意了再盖。

## 施工

- `build(design_id=…, target=锚点, rotation?, name?)`：图纸原点落在锚点上。`target` 可以是 `here`、记住的地名、观察编号、坐标（省略 `y` 取地表）。
- 盖完会自动记一份建筑档案（照哪一版图纸、锚点、朝向、整栋蓝图）。`name` 给这一栋起档案名（不给就用图纸名），结果的 `archive.name` 是实际记下的名字；以后改这一栋就指着它，记进笔记。
- 材料：施工缺什么会自己去拿；材料多（几百块）时先用 `obtain` 分批备齐主材，免得施工中途一趟趟跑。材料用完会建到材料尽头停下（`partial`，问题 `NEED_ITEM` 写明还缺什么）：补齐后**再下达一次同样的 `build`**，会从没建完的地方接着盖，不会重盖已经对的格。
- 施工途中天黑、饿了，生存需求会先插进来，处理完接着盖，不用重新下达。
- 读结果：`cells` 里每种结局几格（对上了、放下了、清掉了、还缺、放不了、受保护……），`problems` 按原因列出没做成的格和坐标，`temporary_blocks_left` 是没收回的垫脚方块（下一次施工会接着收），`check` 是收场时对整栋的比对（见“改已有的房子”）。
- 只放一个方块（例如墙上一支火把）：`build(block=…, target=…)`，不用画图。几格以上的东西用图纸或 `cells` 一次下达，不要用 `sequence` 串一格一格的 `build`：盖得慢，每一步还各报一条进展，主播那边刷屏。

## 改已有的房子：装门、放床、开窗、修补、加建

俯视网格只画一层，看不出门洞在哪、地面多高，照它去挖会拆到墙。改一栋已有的房子按四步来：读现场 → 挑格 → 改层图 → 补建后看比对。

### 读现场

- `design(operation=read_site, target=…)`：当场返回，不动角色、不改世界，把这一栋读成一版新图纸（一个层图对象），同时给布局。
- `target` 写这一栋的档案名（`{"kind":"landmark","name":"档案名"}`；`build` 结果的 `archive.name`，`observe(what=world_memory)` 里也看得到），就读档案的范围，另给 `check`：档案里的蓝图对现场比，哪里被拆了、被改了一眼看出来。
- 没有档案（不是 `build` 盖的）就指着它的一面墙、一扇门、坐标、记过的地点或 `here`，从那一格自动框住整栋，三条边都不超过 32 格，更大的给 `radius` 分块读。这时同时给 `name`，用这个名字建一份档案，结果的 `archive` 就是档案名，后面补建都指着它。
- 只读看得见的格：站在屋外读，屋里多半是 `?`（`unseen` 很大）。要放床、看屋里空地，先走进屋里再读一次。

### 挑格

- `site` 是层图：每层一张字符图，北朝上、东朝右；第几行是 z、一行里第几个字符是 x、层的 `y` 是高度，都是相对层图对象 `location` 的偏移；`legend` 把字符对到材料；`.` 是空着，`?` 是没看到。`anchor` 是设计原点落在的那一格。
- `layout` 用世界坐标给出布局：`floors`（每层地面方块的 `y`、净高）、`doors`（`at`、朝向、铰链、开着没、`inside` 屋里那一侧）、`openings`（门洞、窗洞，在哪面墙）、`windows`、`beds`、`climbs`（楼梯梯子连着哪几层）、`facilities`、`free_floor`。地面多高看 `floors`，不从网格猜。
- 放床：从 `free_floor` 挑（屋里有顶、能站、头上两格空；`from` / `to` 就是人站的那一层，床放在这一层，不用往下挖）。床占两格，床脚和床头沿朝向连着，两格都要在空地里，对着层图确认那两格是 `.`。空地不够就换一片或先挪走挡着的东西，不拆墙、不挖地面去凑。
- 装门：门装进 `openings` 里的门洞（一格宽两格高），下半在下、上半在上；已有的门在 `doors` 里。要新开门洞，在墙上挑一格宽两格高、屋里和外面都有地方站的位置。

### 改层图、补建

- 改 read_site 给的那一版：`design(operation=update, design_id=…, edits=…)`，对象名照 `site` 的 `name`（读现场出来的叫 `现场`）。
  - 逐格改用 `set`：`{"objects": [{"name": "现场", "set": [{"at": [x, y, z], "material": "材料名"}]}], "materials": {新用到的材料}}`。`at` 写 `[一行里第几个字符, 层的 y, 第几行]`，都从 0 数；从 `layout` 的世界坐标换过来是减去 `anchor` 再减去 `location`。材料表里已有的直接用（读现场按方块起名，例如 `spruce_planks`），新材料同时写进 `materials`。
  - 整层换用 `layers`：按 `y` 对上，只换写到的那几层。
  - 门、床两格都要画：门的下半、上半各一格（`half` 写 `lower` / `upper`；朝向不讲究可以不写，要和原来那扇一样就抄 `doors` 里的 `facing`）；床的床脚、床头各一格（`part` 写 `foot` / `head`，两格 `facing` 一样，都朝床头那一头）。要挖空一格就对到一个 `minecraft:air` 材料；写 `.` 只是不声明，施工不管那一格。
- 补建：`build(design_id=新一版, target={"kind":"landmark","name":"档案名"})`。锚点、朝向照档案，不给 `rotation`；对上的格跳过，只做改了的格。`target` 写坐标就是在那里另盖一栋，不是改这一栋。
- 只补墙上一支火把这种单格：`build(block=…, target=那一格)` 也行，落在档案范围里会并进那一栋。

### 看比对

- 施工本身做成没有照 `status`、`cells`、`problems` 算；`check` 是收场时整栋对图的比对：`differences[]` 列出没对上的每一格（`at`、`wanted`、`found`），拆墙时碰掉的火把、流进来的水都在里面；`complete` 为 false 是有格没看到；`extra` 是范围里没声明却有东西的格，只作参考。
- 改建结果还带改完的 `layout`：门进没进 `doors`、床进没进 `beds` 在这里核对，再交付。
- 没对上的格读清是什么再决定补不补：要补就再改一版层图补建，或 `build(cells=…, target=档案名)` 打补丁（`offset` 相对档案锚点），不把同一份图原样重下。

## 照着现成的结构盖

主播给了结构文件（放在实例的 `schematics/` 目录里）：`build(file=文件名, target=锚点, rotation?)`，认原版 `.nbt`、Litematica、Sponge 和 `design` 导出的 `.json`。展示框、盔甲架这类摆设不装，结果里写有几个；箱子里的东西、告示牌的字不搬。自己画的图纸要留给以后用：`design(operation=export)`。

## 常见坑

- 一张图纸写成一个实心大盒子：盖出来是一坨方块，进不去。
- 屋顶、梁压低了室内，或装饰堵了门窗。
- 同一个 `build` 失败后原样重下：先读 `problems`，是缺料就补料，是够不着就换锚点或改图，是受保护就换地方。
- 改房子时照俯视网格估门洞和地面高度，挖错一格就拆了墙：先 `read_site`，坐标从 `layout` 和层图里取。
- 为了放床“清出两格地面”：床放在 `free_floor` 那一层的地面上，不用挖。
- 默认许可只拆天然方块；`change_blocks=any` 会拆改别人的东西，没有主播明确同意不要用。

## 何时上报

施工要拆改玩家的东西（`NEED_APPROVAL`）、材料怎么都弄不到、主播要的地点盖不下（太窄、在别人领地里）时，写清缺什么、试过什么，问主播。盖好后交付时说清盖了什么、在哪、用了多少料。
